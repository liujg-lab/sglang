# 服务配置扫描

这份报告回答的是：固定宽度的 OPT 树在这套 Target / Draft 上用哪一组 N、τ、lookahead 和 KV 复用，以及什么时候改走 Target-only。数字来自本机 `notes/raw/` 里的 `precheck.json`、`all.csv`、`group-a.csv`、`group-b.csv`、`ext.csv`、`ext-decision.json`、`ext-step0.json`、`ext-step1.json`、`fit-all.json`，这些原始表不进仓库。吞吐是两次重复的均值，除非另写。

共同硬件、采样和指标口径见 [README.md](README.md)。这一阶段的早期格子是 lookahead 关、KV 复用关。后面的 A/B 组把 KV 复用打开。lookahead 只在 b=1 的 S3 和 B 组里打开过，没有 b>1 的 lookahead 格子。

## 预检

NPU 卡 2 和 3。N=8 和 N=32 都完成了 CUDA graph 捕获，图留在服务里。N=32、b=8、前缀 1024、`max_new_tokens=320` 跑完 64/64，没有 OOM，9 个统计窗口。

同一配置三次吞吐 69.66、69.45、69.74 tok/s，摆动 0.43%。改 τ 只重启 Draft：τ=0.2 时，只重启 Draft 与两端都重启，4/4 的输出 token 相同，接受深度直方图相同。改 N 则两端都重启。

## 合成前缀和自然短提示不是同一分布

合成前缀（ell=1024 的填充，`ignore_eos`，`max_new_tokens=192`）在 N=8、τ=0.1、b=1 上是接受长度 6.833、轮时 91.33 ms、吞吐 74.81 tok/s。同一公式下的自然短提示两次是接受长度 3.822 和 3.803、轮时 77.57 和 77.63 ms、吞吐 49.27 和 48.99 tok/s。

`6.833 / 3.822 × 77.6 / 91.33 ≈ 1.52`，和两条序列吞吐比 1.52 一致。差别来自文本，不是前缀公式坏了。自然短提示这两次的变异系数是 0.41%，两倍带宽 0.82%。

## 这一阶段写下的结论，以及后面怎么读

`ext-decision.json` 的原结论是：停掉 TollTree。短提示的 B 组用 N=16、τ=0.4、lookahead 开、KV 复用开。投机开到 b=6，持续的 b=8 用真正的 Target-only，不用 `skip_rpc_high_bs`。4096 token 前缀上 τ=0.2 到 0.4 比 0.8 快。这些比较对应测到的 3–5 ms 实验室 RTT。

后面的成本门控没有把 N=16 收成全服务宽度。`fit-all.json` 在 65 行上得到 b=1、4、8 的最好 τ 都是 0.4，V=0，对照变异系数 0.29%，结论是增益在 2% 或噪声以内，停止按请求改 τ，保持一个固定 τ。`item7-bound.json` 登记的静态规则是 N=8、短前缀 τ=0.8、长前缀 τ=0.4，短 b≥7 或长 b≥3 走 Target-only；同一份文件写明没有在线的流量比例，这条规则不单独决定生产配置。

短前缀大 batch 上，A 组 τ=0.8 的点估计高于 τ=0.4（b=4 是 156.57 对 149.52，b=8 是 192.51 对 187.99）。b=1 上 0.6 与 0.8 的差在重复带宽里。两套 τ 都留在对应的表里。全服务宽度保持 N=8；KV 复用在 S3 之后的测量里保持打开；lookahead 只有 b=1 的数据。
