# 成本与正确性门控

这份报告按门控条目写判据和结果。原始文件在本机 `notes/raw/gate/`，不进仓库：`item1-verdict.json`、`item2-hcfg.json`、`item3-cost.json`、`item4-depth.json`、`item4-existing.json`、`item5-prediction.json`、`item5-result.json`、`item6-memory.json`、`item7-bound.json`。拟合摘要是 `notes/raw/fit-all.json`。服务配置和 A/B/C 组的吞吐表见 [01-serving-config.md](01-serving-config.md)。

共同硬件见 [README.md](README.md)。这一阶段的服务宽度是 N=8。预测文件 `item5-prediction.json` 写明在 b=2 的实测之前已经落盘。

## 拟合在进门控之前已经得到的结论

`fit-all.json` 用了 65 行。

| 问题 | 结果 |
|---|---|
| Q1，b=1 留出 16 格 | 每层时间相对误差 2.85%，Target 侧轮时相对误差 2.32% |
| Q1，b>1 留出 16 格 | 每层时间相对误差 7.81%，Target 侧轮时相对误差 6.45% |
| Q2，24 格 | 平均残差 5.58%，没有缺行 |
| Q3 | 全局 τ=0.4，V=0 |
| Q4 | b=1、4、8 的最好 τ 都是 0.4 |

对照变异系数 0.29%。书面结论是：V 低于 2% 或落在噪声里，停止自适应，保持固定 τ。

## 第 1 项：输出是不是验证 bug

对照是温度 0。A1 对 A2 有 15/16 条请求一致。唯一分叉在请求 0 的第 249 个 token：一边是 17，一边是 15，A1 的 top-2 是 17 和 23，自然间隙为 0。

投机输出里每一个分叉 token 都在 A1 的 top-2 里。最大间隙 0.25，等于 A1 对 A3 的最大间隙。分叉率 `spec_h` 为 0.00767，上限是 0.0224，在 3 倍以内。

吞吐：A1 30.734，A2 30.781，A3 两次 221.496 和 222.231。记录的 git 是 `0c6da7e45820bbd7c8aafa2b1fbbc4f548f3731f`。

`item1-verdict.json` 的 `bug` 是 false，后面的格子没有因此停。`item1.json` 里另有一个 `bug: true`，那是脚本把这处分叉记成了失败，不作为结论。

## 第 2 项：换配置之后输出差多少

以 S3、N=8、τ=0.8、b=1 的第一次为基准，和 τ=0.4、τ=0.2、N=16 τ=0.4、以及 A 组 N=8 τ=0.8 b=4 做逐请求比较。完全相同的请求数在 2/16 到 4/16 之间。

`h_cfg × 接受长度` 的最大一对是 0.0295（S3 τ=0.8 对 A 组 b=4）。判定是 `approximate`：配置之间的输出差保持在这个量级，没有把它当成正确性失败。

## 第 3 项：成本模型在留出格上的误差

只用短前缀拟合、再拿到热的 4096 前缀上时，16 个留出格全部超过 10%，相对误差从 24.9% 到 54.6%，`short_pass` 为 false。预测文件里的对应说法是：短前缀模型在热的 4096 上偏差 41%–55%。

加上前缀长度项之后，在热的 N=16、4096、b=1 上检查了 5 格，4 格在 10% 以内（约 8.5%–10.0%）。没过的一格是 `B-n16-t0.2-b1-r1-l4096`：预测轮时 97.3 ms，实测 121.7 ms，相对误差 20.1%。因此 `n16_pass` 仍是 false，`model_pass` 是 false。冷的 B、τ=0.2、r1 那一格按预测文件的说明排除在这 5 格之外。

lookahead 打开时，D_crit 比按层时间累加出来的值大约多 2–3 ms。这是记录里的空隙，例如短提示 N=16、τ=0.4 的空隙约 2.2 ms，4096、N=8、τ=0.2 的空隙约 2.9 ms。

## 第 4 项：接受深度

`q_d` 是走到深度 d 的比例。b=1 和 b=4 在 d≤4 上相差不超过 0.03。`1 + Σ q` 和接受长度的差在 3% 以内，这几格的 `consistent_3pct` 都是 true。

短提示、N=8、τ=0.2、b=1：接受长度 3.808，`1+Σq` 为 3.812，r=0.709，`c_min=0`，`c_max≈0.51`。

4096、同一配置：接受长度 4.636，`1+Σq` 为 4.650，r=0.766，`c_max≈0.55`。

长前缀减短前缀的 r：b=1 是 0.057，b=4 是 0.026。`c_min` 为 0，所以没有因此把 τ 调低。截断参数 c 不能从这些边缘直方图辨认出来；接受深度也不会超过树深。`share_across_b` 为 true。

4096、b=4、τ=0.2 的两次接受长度是 4.463 和 4.528，这是后面窗口实验对照用的同一对格子。

## 第 5 项：b=2 的预测和实测

预测在开跑之前写入。门槛是相对误差 10% 以内，并且投机和 Target-only 的快慢方向一致。一条超过 10% 就停，不写 tuner。

| 格 | 配置 | 预测 tok/s | 实测 | 相对误差 |
|---|---|---:|---|---:|
| P1 | 短前缀，b=2，τ=0.8，投机 | 103.13 | parser 96.83，client 97.05，轮时 73.15 ms，接受长度 3.544 | 6.5% |
| P2 | 对应的 Target-only | 58.41 | client 59.93 | 2.5% |
| P3 | 4096，b=2，τ=0.4，投机 | 75.29 | parser 58.04，client 56.29，轮时 126.7 ms，接受长度 3.677 | 29.7% |
| P4 | 对应的 Target-only | 55.65 | client 53.21，预热 27.48 | 4.6% |

P3 的热缓存记录是新 token 2048、缓存 token 63488。P1、P2、P4 在 10% 以内。P1 实测高于 P2，P3 实测高于 P4，快慢方向和预测一致。P3 从 75.3 测到 58.0，约 30%，门控失败。没有写 tuner。

4096、b=2 上，投机的 58.04 仍然高于 Target-only 的 53.21。模型把这一格的投机优势估大了，符号没有估反。

## 第 6 项：显存

只看启动日志，没有新开请求。N=8 和 N=16 的实现都是 `tree_paged_fia`，`fallback_reason` 为空，包括后来服务 4096 格子的 N=16 日志。

| 配置 | 占用 | 结束时可用 | 捕获耗时 |
|---|---|---|---|
| Target-only | 0.85 GB | 11.31、11.61、11.61 GB | 7.14、5.97、7.0 s |
| N=8 | 1.05、1.04、1.05 GB | 11.11、11.42、11.11 GB | 77.31、75.09、78.64 s |
| N=16 | 1.38 GB | 11.08、10.78、11.08 GB | 79.63、75.46、73.92 s |

额外的 M9 是 0.20 GB，M17 是 0.53 GB，1+9+17 合计 1.58 GB。扣掉额外的 M9 之后还剩 10.91 GB，底线是 1.252 GB。`pass` 为 true。K=16 在 b=1 上没有被显存门控排除。

## 第 7 项：静态上界

这一项 `ran` 为 false。它用已经测到的格子做上界，没有新跑。登记的规则是：N=8；短前缀 τ=0.8；长前缀 τ=0.4；短 b≥7 或长 b≥3 走真正的 Target-only。

| 格子 | 静态配置 | 该列里见过的最好值 | 空隙 |
|---|---:|---:|---:|
| 短，b=1 | 62.6 | 64.1 | 2.4% |
| 短，b=4 | 156.6 | 156.6 | 0 |
| 短，b=6 | 179.0 | 179.0 | 0 |
| 短，b=8 | 221.4 | 221.4 | 0 |
| 长，b=1 | 47.2 | 53.3 | 12.9% |
| 长，b=4 | 105.2 | 105.2 | 0 |

短 b=8 和长 b=4 的最好值就是 Target-only（221.4 和 105.2）。长 b=1 上，N=16 的 53.3 比静态的 N=8、τ=0.2 高 12.9%。文件给出的混合上界是 `s1 × ((1−f)×0.024 + f×0.129)`。没有在线的 s1 和 f，所以这不单独选一个生产配置。若 s1=0.5，要让混合空隙值得换配置，f 需要到 0.15；s1=0.3 时，f 需要到 0.41。

## 门控之后留下的服务点

第 1 项不是验证 bug。第 5 项因为 P3 偏差约 30% 失败，不写 tuner。显存允许 N=16 的 b=1，但全服务宽度仍用 N=8：N=16 只在 b=1 上更高，b=8 上更慢，见配置报告里的 S2。

KV 复用保持打开。lookahead 只有 b=1 的测量。τ 保持固定，不按请求切换。短前缀上 A 组 τ=0.8 的大 batch 点估计更高；长前缀上 0.2 到 0.4 比 0.8 快。持续的短 b=8 和 4096 的 b=4 用 Target-only 更快（221.4 对投机约 192；105.2 对投机约 84）。4096 的 b=2 上投机仍更高（58.04 对 53.21），只是成本模型没有预测准。
