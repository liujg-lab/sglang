# E1 门槛修订

修订先于 E1′ 重跑。下面的数字都来自已经落盘的日志，没有为修订新开服务。

## 为什么原来的 0.82% 不能用在这一格

0.82% 是短前缀、b=1 的重复噪声。4096、b=4 的对照自己两次之间，吞吐是 84.81 和 84.06，相对差 0.89%；接受长度是 4.463 和 4.528，相对差 1.46%。对照自己就过不了 0.82%。

E1b（`WINDOW=full`，核对打开）的 logits 已经对齐：1032 行最大差值为 0，top-N 一致率 100%，回退为 0。这是等价证据。吞吐和接受长度的偏差不再当成影子行错误。

## 不用新跑已经核对的三件事

### r1 的 Target 验证前向

r1 和 r2、以及对照 G4L 的两次，Target 预填充都是 `#new-token` 合计 4096、`#cached-token` 合计 126976。r1 不是冷缓存，也没有整段重新 prefill。

r1 的验证前向均值 68.3 ms 是被一个窗口的 85.6 ms 拉上去的。中位数是 60.2 ms，r2 的中位数是 58.7 ms，对照是 58.0 和 58.6 ms。按下面的作废规则，中位数只偏了约 2.5%，r1 不作废。

这次没有在 r1 当时抓 `npu-smi`。实验前后卡 2、卡 3 都只有本任务的 Target；卡 0 上始终是另一个用户的进程，没有动过。

### r2 多出来的约 4.9 ms

对照轮时均值 213.0 ms，r2 是 217.9 ms。拆开之后：

| 项 | 对照均值 | r2 | 相对差 |
|---|---|---|---|
| 每层 GPU | 12.24 ms | 12.27 ms | +0.2% |
| 每层 host | 1.732 ms | 1.904 ms | +9.9% |
| 每轮层数 | 6.613 | 6.849 | +3.6% |
| 树深 | 5.04 | 5.14 | |
| D_crit | 118.8 ms | 124.7 ms | 随层数涨 |
| D_crit / 每轮层数 | 17.96 ms | 18.21 ms | +1.4% |
| Target 验证前向中位数 | 58.3 ms | 58.7 ms | +0.4 ms |

GPU 和 D_crit/层数都在 3% 以内。多出来的轮时主要是每轮层数多了，不是每层 GPU。host 高了 9.9%，但这一格开着核对，每 100 层在关键路径上多跑一次全量前向。核对打开时的 host 和吞吐不作为影子行成本。E1′ 把核对关掉再比。

### b>1 是否走 CUDA graph

已有日志没有树层的图命中计数。`cuda graph: False` 只出现在 Prefill 行上，不能当成树层。

代码上，`TARGET_VERIFY` 的 `is_cuda_graph()` 为真。b=4、宽度 8 能对上已捕获的 batch 和 ntpb 时，`CudaGraphRunner.can_run` 会走重放，KV 下标写进图缓冲，不走 `triton_backend.py` 里按真实长度现分配的那条 eager 路径。对不上才落到那条 eager 路径。

E1′ 起，b>1 的树层前向会计 `opt_verify_graph_layers` 和 `opt_verify_eager_layers`。哪边不是 0，成本拟合就按哪边标。eager 占多数时，kernel 启动开销单独算，不并进「前缀 KV 字节 / 带宽」。

## 修订后的 E1′ 判据

正确性维持原标准，E1b 已经通过，E1′ 不再开核对：|Δlogit| ≤ 1e-2，top-N 一致率 ≥ 99.9%。

成本，B 相对 A，主判据：

- 每层 GPU ≤ +3%
- 每层 host ≤ +3%
- D_crit / 每轮层数 ≤ +3%

吞吐，次判据：

```text
|mean(B) − mean(A)| / mean(A) ≤ max(A/A 相对带宽, 1%)
A/A 相对带宽 = A 组各次吞吐的最大相对差
```

作废，预先登记：同一次运行里，Target 验证前向的窗口中位数，偏离同一组各次中位数的中位数超过 10%，这一次作废并重跑。只看 Target 侧，不看 Draft。

配对接受长度：同一 prompt（前缀前 8 个 token 加长度）在 A、B 之间的每请求平均接受长度之差，不超过 A 组内部同样配对的最大差。logits 已经完全一致，这里不应有系统性差别。

host 超过 +3% 时，不进入 E2。先把影子行改成只追加新的树列，不再每层重写整个前缀，然后重跑 E1′。

## E2 预测（在 E1′ 通过之后才用）

短前缀 b=4 的每层 GPU，G4 两次是 5.209 和 5.326 ms，L_s = 5.268 ms。全量前缀对照是 12.24 ms。可省的部分 P = 6.97 ms。

短前缀按成本拟合用过的类长度 ℓ_s = 93。s = 64。

```text
L(w) ≈ 5.268 + 6.97 · (64 + w − 93) / (4096 − 93)
```

w=512 时预测约 6.11 ms，相对 12.24 ms 大约降 50%。

带宽上限用实测的 114688 字节/token（28 层、8 个 KV head、head dim 128、bf16）。b=4、4096 前缀每层 KV 约 1.88 GB，按 936 GB/s 约 2 ms。16 个 query head 对 8 个 KV head 各读一遍则约 4 ms。P = 6.97 ms，大于 4 ms，所以若窗口有效，省下的应多于纯带宽那 4 ms。

停止线不变：L(512) 相对首尾 A 的每层 GPU 降幅不到 20%，O1a 和 O1b 都停。

## E1′ 第一轮（核对关闭，整段前缀每层重写）

六次交替，没有作废。b>1 树层 `opt_verify_graph_layers` 合计 13858，`opt_verify_eager_layers` 为 0。树层走的是 CUDA graph 重放，不是按长度现分配的 eager 路径。

GPU +0.6%，D_crit/层数 +1.7%，吞吐差 0.91%，A/A 带宽 2.88%。配对接受长度差 0.23，小于 A 组内部 0.97。只有每层 host +11.0% 超过 +3%。因此没有进 E2。

第二轮（WKV3）同一轮里只追加树列，前缀变化时仍整段重抄。GPU −2.4%，D_crit/层数 −1.5%，吞吐差 0.14%（A/A 带宽 1.59%），配对接受长度差 0.63，小于 A 组内部 0.95。host +9.1%，仍超 +3%。相对第一轮的 +11.0%，少抄的那几层只拿回约 2 个点，所以 host 差主要不在整段前缀拷贝上。图命中 14047，eager 为 0。没有进 E2。

第三轮（WKV4）曾在前缀变长后跳过重抄。接受长度从约 4.6 掉到 2.39，吞吐从 84.3 掉到 68.1。提交会改写真实行的索引，上一轮树列不能当成新前缀。这段已撤回，代码回到 WKV3 的行为。WKV4 的图命中仍是 13736 / eager 0，只说明路径，不进入成本判断。

## E2 之前的判据：绝对预算

E1′ 按当时的 host +3% 判为不通过。那份记录保留。不再为这 0.11 ms 继续改刷新。下面的改判据理由不靠那次吞吐。

host 时间在关键路径上，并且和 GPU 时间串行。每层结束时 `_commit_prob_rows` 经 `host_topk_rows` 做一次 `.cpu()`。下一层的准备开始时，stream 已经空闲。`opt_layer_host_us` 在 `ev0.record()` 之前停下，所以不在 `opt_layer_gpu_us` 里面。`ev0..ev1` 仍包含 `_run` 内部 stream 空闲的时间，因此 host 加 GPU 是关键路径的上界，不是纯 GPU 忙碌时间，也不再减去 `launch_us`。

原门槛是 1.2 ms 的 3%，大约 36 µs。几次 eager 小 kernel 的启动就会超过它。

另有一条只说明为什么停止优化刷新，不作为门槛：WKV2 到 WKV3 每层只少约 0.02 ms，重抄前缀不是大头。剩下的是每层固定的准备。WKV4 也是少抄，修好了也碰不到这部分。WKV4 接受长度掉到 2.39，Draft 读到了错误的 KV。可能是已接受节点的槽被搬走，或者回包后补算的一层没有写进影子行。这一版不修。

新判据只在 E2 这一场里算。分母是 `opt_layer_forwards + opt_layer_forwards_deferred`。

```text
overhead  = (host+GPU)_B_full − (host+GPU)_A
saving(w) = (host+GPU)_B_full − (host+GPU)_B_w
```

影子行开销：`overhead ≤ 10% × saving(512)`。saving(512) 没有达到下面那条线时，这条不再单独判。窗口值不值得：`saving(512) ≥ 20% × (host+GPU)_A`。达不到就停 O1a，窗口保持默认关闭。

短前缀 b=4、τ=0.2 的 G4 草稿日志，parser 口径：

- r1 GPU 5.209 ms，host 1.156 ms
- r2 GPU 5.326 ms，host 1.116 ms
- `L_s` = 5.268 ms，host = 1.136 ms，合计 6.404 ms

预测锚只用 WKV3 这场的 A，GPU 12.470 ms 加 host 1.205 ms，合计 13.675 ms。E2 的 20% 线用本场的 A，不用这个锚。

```text
P = 13.675 − 6.404 = 7.271 ms
L(w) ≈ 6.404 + 7.271 · (64 + w − 93) / (4096 − 93)
```

w=512 预测约 7.28 ms，saving 约 6.39 ms，约为锚点合计的 47%。20% 线约 2.74 ms/层。

分支：

- saving(512) < 20%：O1a 停，代码保持默认关闭。
- saving ≥ 20% 且 `a_w ≥ a*`：先把每层准备压到 overhead ≤ 0.03 ms，重做核对，再跑 E4、E5。`a* = 105.2 × T_round / 4000`。
- saving ≥ 20% 但 `a_w` 不过：只补一格 s=128、L0=1024。还不过就停。

## E2 这场的结果

本场 A 的 host+GPU 是 13.675 ms。B_full 是 13.518 ms，overhead −0.157 ms。saving(512) 是 6.109 ms，高于 2.735 ms 的 20% 线。w=1024、512、256 的 `a_w` 都过了 `a*`。分支是先收每层准备，再跑 E4、E5。三个过线宽度里吞吐最高的是 w=256。

准备改完后重做核对，full 和 w=8192 的 logits 最大差是 0，w=512 的索引不一致是 0。一次 A/B 的 overhead 是 −0.273 ms。E4、E5 用 w=256，判定在 `e4e5-verdict.json`。窗口默认仍然关闭。
