这是 2026-11-09 价格设计当时写下的步骤，不是当前要跑的计划。已有结论在 `validate/DECISION.md` 和 `raw/gate-window/DECISION.md`。

## 实验规划

### 通用约定

- **只做在线实验，不做离线 replay。** 在运行中的 Target 服务上给已有输出打分可以用。
- **扫 τ 时只重启 Draft：** 省掉 Target 约 75 秒的图捕获。每组第一格要确认 Target 没有 spec_shape 拒绝，也没有会话重置失败。
- **每格的目录：** `validate/<实验>/<格>/<次>/`，内含两端日志、客户端记录和 `meta.json`。`meta.json` 记 git hash、两端参数、环境变量、网络延迟设置、新预填充和缓存命中 token 数。
- **判定先写进 `validate/DECISION.md` 再跑。** 改判据要先写清理由，理由不能依赖这一次的结果。
- **噪声门槛按场景测：** 每个场景先测 A/A 带宽，吞吐判据取 `max(A/A 带宽, 1%)`。4096、b=4 的 A/A 带宽是 1.6%–2.9%。
- **主判据用不受请求组合影响的量：** 每层耗时、按 rid 配对的接受长度。总吞吐作为次判据。
- **A/B 交替跑：** A B A B A B，只在同一场次内比较。
- **Target 侧异常作废：** 某次的 Target 验证前向，每轮中位数偏离同组中位数超过 10%，作废重跑。
- **成本按关键路径的绝对量算：** host 和 GPU 是串行的，比较二者之和。
- **按请求的配对只到第一次分叉为止：** 换配置后文本会走岔，分叉之后的部分只进总体统计。
- **每格都带无损护栏：** 按差距分档统计翻转率，和 Target-only 跨形状基线比较。
- **数据集：** 合成填充前缀的接受长度比自然提示高约 2 倍（6.8 对 3.8），不能拿来下性能结论。4096 的格子要用互不相同的前缀，不能只重复 8 条。
- **网络延迟：** 用用户态 TCP 延迟代理加在 Target 和 Draft 之间（不需要 sudo），或者由用户执行 `tc netem`。每组第一格用 `opt_step_rtt_us` 确认延迟确实增加。

### 一、O1a：Draft KV 窗口（已完成，默认关闭）

Draft 的树层只对 sink（s=64）、最近 w 个 token 和树列做 attention，通过影子 `req_to_token` 行实现。前缀 ≥ L0=2048 时生效。Target 用完整 KV 验证，输出不受影响，最多是接受长度下降。开关是 `SGLANG_OPT_DRAFT_KV_WINDOW`。

| 步骤 | 结果 |
|---|---|
| E1：WINDOW=full，核对打开 | 1032 行 logits 最大差 0，top-N 一致率 100%，回退 0 |
| E1′（WKV2、WKV3） | 每层 GPU 和吞吐都在噪声内；每层 host +9–11%（约 0.11 ms/层，约每轮 0.25%）。按原门槛不过，改用关键路径的绝对预算 |
| WKV4：跨轮不再重抄 | 接受长度掉到 2.39，已撤回 |
| E2：4096、b=4，核对关闭 | 每层 host+GPU：A 13.675、B_full 13.518、w=1024 8.179、w=512 7.408、w=256 7.020 ms。overhead −0.157 ms；saving(512) 6.109 ms，超过 20% 线 2.735 ms。吞吐比 A 高 24–27%，接受长度从约 4.70 降到约 4.23。w=512 预测 7.28 ms，实测 7.408 ms。选 w=256 |
| 每层准备优化后 | full 和 w=8192 的 logits 仍完全一致；overhead −0.273 ms |
| E4a：4096、b=4、τ=0.4、w=256 | 110.41 tok/s，同场 Target-only 104.66（+5.5%） |
| E4b：b=2 | 61.74，Target-only 53.21 |
| E4c：b=6 | 132.09，Target-only 138.43（−4.6%） |
| E4d：短前缀、b=4 | 157.46，窗口不生效（前缀 < L0） |
| E5：输出 1024 | 接受长度从首桶到末桶下降 15.1%，完整前缀是 23.6%，没有超出判据 |

**对建模的意义：**
- κ·ℓ 项是真实的：窗口省下了约一半的每层成本。说明长前缀的成本主体在 Draft 的前缀 attention，有效带宽约为峰值的 28%。
- 开窗后 `ℓ_eff = min(ℓ, s+w)`，长前缀请求的每层成本被封顶，"长请求先退出"这个效应会变弱。
- 4096 下的打平点从 b=2–4 之间移到 b=4–6 之间。

**要补的：** E4 只用了 8 条前缀重复。换成 32 条互不相同的前缀（D2）时，窗口关闭下投机 75.21 tok/s，Target-only 98.80 tok/s。粗算开窗后约 94，仍低于 Target-only。要用互不相同的前缀、开窗重跑 E4a 和 E4b。

### 二、4096 输出分叉的排查（已定性：数值放大）

**现象：** 有一条前缀在 b=1 时每次都在 t=72 写成 56056，Target-only 是 656，领先 6.8–8 nat。b=4 时没有出错，因为两次的轮次切分差一位。D1、D2 里还有 1–2 处差距 > 1 nat 的分叉。

**已排除：**

| 嫌疑 | 依据 |
|---|---|
| 窗口、τ | 窗口关闭也出现 |
| 惩罚、logit bias | 请求没有开启；惩罚前 top-1 就是 56056 |
| radix 前缀被污染 | 清空缓存后不变 |
| graph update 和 replay 的重叠 | 关掉 overlap 后不变 |
| 选错节点、父链 | h 通过 |
| 页表、页内槽位 | f 通过：4172 个位置都是 `page_id·128 + p%128` |
| 写入槽和读取槽不一致 | e、e2 通过：`out_cache_loc` 等于 `req_to_token`，写入值和 cache 逐位相同 |
| 掩码 | i′ 通过：9 行的前缀列、祖先列、尾部屏蔽都对 |
| attention | 64 层 tree FIA 和 fp32 GQA 一致，余弦 ≥ 0.9999 |
| 已提交前缀的深层 KV | 第 36–43 层都在 decode 对照的噪声内 |
| 行与行之间耦合 | M=1 单独重算和批量第 4 行逐位相同 |
| 量化 | Target 是 bf16，没有量化 |
| 位置和 RoPE | positions[4]=4167，cos/sin 逐位相同 |
| 树形 | 这一轮是一条链，位置等于 4163 + 深度 |

**定位和结论：**
- 槽 4 的残差从第 36 层开始比 decode 对照偏得多，第 42–43 层明显分开，最后余弦约 0.6。decode 对照一直保持在 0.98 以上。
- 第 30–45 层的 8 个子层，局部误差最大 0.00366，decode 对照最大 0.00376，每个子层都只有 bf16 噪声。
- 结论：这个位置对数值噪声特别敏感，噪声逐层放大后翻转了结果，不是代码错误。
- 记录方式：逐 token 一致仍作为记录项，正确性改用统计判据。

**要补的：** Target-only 跨形状的噪声基线。用 D1 加 D2 的 40 条前缀分别跑 Target-only 的 b=1、4、8，再加预填充打分，按差距分档统计翻转率。D1–D4 里的 Target-only 都是同一形状重复，最多只差 0.375 nat，不能当作基线。

### 四、验证

**插桩（还没写）：** 用 `SGLANG_OPT_TRACE=1`、`SGLANG_OPT_TRACE_EVERY=20` 控制，算法本身不改。

| 日志 | 位置 | 用途 |
|---|---|---|
| `[OPT trace step]` | Draft 事件循环，每轮 | Θ̂、R |
| `[OPT trace layer]` | `_forward_verify_batch`，被采样的轮 | 成本表和先验 |
| `[OPT trace req]` | `grow_batch` 结束后 | 每个请求的 Δ 序列、深度、校准标签 |
| `[OPT trace round]` | `grow_batch` 的 finally | ingest 耗时、层数、K |

**前提检验：**

| 前提 | 计算 | 通过 |
|---|---|---|
| (A1) 逐层收益递减 | Δ(k+1) > 1.05·Δ(k) 的比例 | ≤ 10% |
| (A2) 成本可加 | 每个格子内：每层耗时 = c0 + Σ c_i 的残差 | 残差 p90 ≤ 10% |
| ĝ 可预测 | 用 r̂ 预测的继续/停止决策和真实增益的决策，符号相反的比例 | ≤ 10% |
| Θ̂ 测得稳 | EMA 对窗口吞吐的误差；b 变化后的稳定轮数 | ≤ 3%，≤ 30 轮 |

**可以证伪的预测：**

| 编号 | 预测 | 不成立时 |
|---|---|---|
| P-A | 校准后的 π̂ 把每个深度的接受量预测到 ±5% 以内，不校准的 Draft 路径概率做不到 | 退回只用按请求的 ρ |
| P-B | 在线成本表在留出时段上误差 ≤ 5%，包括 4096、b=2 这一格 | 增加分档 |
| P-C | 全局 Θ 优于单轮比值；请求之间越不一样，差距越大 | 论文删掉这条贡献 |
| P-D | 树深和验证数随 RTT 上升（RTT 4、20、50 ms） | 重新审视 R 进入模型的方式 |
| P-E | 混合负载（b 随负载变化）加 RTT 时间表下，比最好的静态规则高 ≥ 5–8%，离每格事后最优 ≤ 2% | 主线改为系统实现、窗口和成本模型 |

**消融：**
- 验证集：硬截前 N 个、`max(N, κ)`、J、J + frontier 探索。在 N=4、8、16，b=1、4，短前缀和 4096 下比较**吞吐**，同时记录接受长度和深层校准误差。预期 N≥8 时差别很小，b=4 时 `max(N, κ)` 的整批 K 会被个别请求抬高。
- 深度规则：全局 Θ 对单轮比值；直接用 Δ 对用 r̂ 预测。
- 成本：离线拟合对在线查表。
- 选臂：模型引导对不看模型的 bandit。
- 去掉校准；去掉 c0 项；Θ 固定。
