# V0、V1、V5、V6 判据

这些阈值在开跑之前登记。跑完后的数字写在后面的「结果」，不改这里的标准。窗口默认仍然关闭。不开始 V2、V3。

## V0 代理

| 项 | 通过标准 |
|---|---|
| 吞吐 | \|mean(P0) − mean(D)\| ≤ max(D 组内两次的相对差, 1%) |
| R | P0 比 D 多出 ≤ 0.5 ms |
| 接受长度 | 两臂之差在 D 组内两次之差以内 |
| RTT 校准 | 20 ms 和 50 ms 两档，R 的增量分别在 20±1.5 ms 和 50±1.5 ms 以内 |

R 是 Target 的 `opt_step_rtt_us / opt_step_rtt_samples`。客户端吞吐是 Σ `completion_tokens` / (最晚 `t_end` − 最早 `t_start`)。

## V1 翻转基线

- 每一档里，投机的翻转率的 95% 置信上界 ≤ Target-only 跨形状基线的 2 倍。
- ≥ 3 nat 那一档如果显著偏高，按疑似 bug 处理，这一步不改代码。

主指标是 teacher：一次运行的文本对预填充 argmax，所有位置都参与。辅助指标是 pair：两次运行之间，只统计到第一次分叉。

## V5 步时

| 项 | 通过标准 |
|---|---|
| 走图 | `graph` 列应全部为 True。有 False 就是 eager 步，这一格单独标出 |
| 两次之间 | 吞吐中位数相差 ≤ 3% |
| 和已有数值对比 | 短前缀 b=1、4、8 应在 30.7、114.3、221.4 tok/s 的 ±5% 以内；4096 b=4 应在约 105 tok/s 的 ±5% 以内。偏差大说明环境变了，后面的对比用这次新测的数 |

## V6 窗口

- S1 的平均吞吐和 V0 里同配置的非流式结果相差 ≤ 2%。超过则流式影响了测量，改用 Target 日志按窗口统计。
- 窗口长度取「分辨 3% 所需窗口数 × 每窗口秒数」最小、且自相关 < 0.3 的一档，登记为慢环的窗口长度和最短比较周期。
- 分辨 3% 需要几十分钟时，慢环在线上只能分辨 5% 以上的差距。

## 开跑前核对

- Decode batch 样例行匹配 `npu graph`。现有日志里 TP1 的 Decode batch 行数是 0，拷贝里仍跳过 `TP1]`。
- 短前缀 64 条，token 长度最小 1、中位 18、最大 1751、平均 93.5。V0 用固定的前 8 条预热、前 32 条计分。
- `l4096` 由 `ell4096x8.jsonl` 和 `ell4096-unique32.jsonl` 按 `input_ids` 去重，得到 40 条。`l2048` 是每条的前 2048 个 token。
- 16-token、`--top-logprobs 5` 的返回有 16 个 `output_ids`，每个位置 5 个 `[logprob, token_id]`。
- Target-only 捕获了 bs 1、2、4、6、8。`max_total_num_tokens=138496`，装不下 40×4096。V5 的 l4096 用前 16 条。
- 第二次 l4096 预热的 `cached_tokens` 全是 0。40 条前缀本身就超过 KV 池，前缀没有留在 radix 里。

## 结果

原始格子留在本机 `notes/raw/`，不进仓库。本地摘要在 `notes/validate/raw/`，同样不进仓库。窗口默认值没有改。没有改无损口径的实现。没有开始 V2、V3。没有执行 `tc`。

### V0

地址写成字面量 `127.0.0.1` 时，传输层会改成 IPC，TCP 代理不在路径上。P0 因此用 `localhost:30039`，它解析到 127.0.0.1，但走 TCP。代理上游是 `127.0.0.1:30019`。窗口关闭，lookahead 关闭，Target 和 Draft 的 KV 复用都打开。N=8，τ=0.8。

`[OPT accept]` 在窗口关闭时没有打出来。接受长度用回合计数 `accepted_tokens_including_bonus / verify_requests`。

| 臂 | 吞吐 tok/s | R ms | 接受长度 |
|---|---:|---:|---:|
| b=1 D | 59.04，58.91 | 22.27，22.32 | 3.601，3.601 |
| b=1 P0 | 58.96，60.34 | 22.44，22.29 | 3.601，3.601 |
| b=4 D | 152.35，154.78 | 41.05，41.09 | 3.532，3.504 |
| b=4 P0 | 152.39，153.67 | 41.17，40.80 | 3.494，3.517 |
| b=1，加 20 ms | 44.27 | 44.05（增量 21.75） | 3.601 |
| b=1，加 50 ms | 31.84 | 75.48（增量 53.18） | 3.601 |

- b=4 的吞吐、R、接受长度都过线。P0 的 R 没有比 D 多出 0.5 ms。
- b=1 的 R 和接受长度过线。吞吐相对差 1.14%，D 组内相对差只有 0.23%，1% 是上限，这一项不过。
- 加 20 ms 的增量是 21.75 ms，比 20±1.5 的上沿多 0.25 ms。加 50 ms 的增量是 53.18 ms，比 50±1.5 的上沿多 1.68 ms。两档都不过。
- 代理进程大约 0.09–0.15 jiffy/s，没有占满一个核。

把代理挪到 Draft 机器后再测一次 b=1：吞吐 58.44 tok/s，R 22.71 ms，接受长度 3.601。相对直连的差在 1% 以内，R 多出不到 0.5 ms，接受长度相同。这一次代理开销过线。RTT 两档仍然在线外，登记的规则因此停住。S1、S2 没有跑。

### V1

预填充打分用 `input_top_logprobs`，`logprob_start_len` 等于 prompt 长度，没有整体错一位。b=1 的 argmax 对上 10114/10240。

同一形状的 b=4 和 b=4′ 全文一致，40/40。b=1 对 b=4 全文一致 6/40，b=1 对 b=8 是 10/40。

Teacher，发出的 token 对预填充 argmax：

| 运行 | <0.5 nat | 0.5–1 | 1–3 | ≥3 nat |
|---|---:|---:|---:|---:|
| Target-only b=1 | 78/966 = 8.07e-2 | 5/822 | 2/2224 | 1/6188 = 1.62e-4，上界 9.15e-4 |
| Target-only b=4 | 75/1013 = 7.40e-2 | 0/820 | 4/2250 | 3/6117 = 4.90e-4，上界 1.44e-3 |
| Target-only b=8 | 57/941 = 6.06e-2 | 5/781 | 3/2261 | 2/6217 = 3.22e-4，上界 1.17e-3 |
| D1 投机 b=4 | 33/713 = 4.63e-2 | 1/539 | 1/1649 | 0/5259，上界 7.30e-4 |
| D2 投机 b=4 | 62/828 = 7.49e-2 | 3/720 | 6/1836 | 1/4776 = 2.09e-4，上界 1.19e-3 |
| D3 投机 b=1 | 88/820 = 1.07e-1 | 4/596 | 0/1760 | 4/4984 = 8.03e-4，上界 2.06e-3 |

2 倍基线用同 batch 的 Target-only teacher 点估计。D1 的 ≥3 nat 上界低于 2×b=4 基线。D2 的上界 1.19e-3 略高于 2×4.90e-4=9.80e-4，但同一批前缀的 Target-only（D2-only）自己的上界是 1.49e-3，不高于对照。D3 的上界 2.06e-3 是 2×b=1 基线 3.24e-4 的大约 6 倍，同一批前缀的 Target-only 在这一档是 0 次。其中一条是 idx 4、t=72，预填充 argmax 656，投机写出 56056，裕度 5.75 nat。

这一档按疑似 bug 记下。这一步不改代码。

Target-only 自己在 b=4、b=8 的 idx 4、t=72 也离开了预填充 argmax 656，写出的是 5443，裕度 6.25 nat。所以这个位置上，预填充、单独解码和投机三者不是同一个 token。

逐条事件在本机 `notes/validate/raw/v1/` 和 `notes/validate/raw/old/*/teacher.txt`，不进仓库。

### V6

T 是 Target-only、短前缀、b=4、流式 600 秒。去掉前 60 秒后，平均 113.68 tok/s。

| 窗口 token | 窗数 | CV | 自相关 | 每窗秒 | 分辨 3% 的窗数 |
|---:|---:|---:|---:|---:|---:|
| 1000 | 61 | 0.81% | 0.05 | 8.8 | 2 |
| 2000 | 30 | 0.64% | −0.39 | 17.6 | 1 |

自相关低于 0.3、且「窗数 × 每窗秒数」最小的一档是 1000 token，大约 18 秒可以分辨 3%。这是 Target-only 的噪声，不是投机的。S1、S2 因 V0 的 RTT 校准出了 ±1.5 ms 而没有跑，所以投机臂的窗口还没有登记。
