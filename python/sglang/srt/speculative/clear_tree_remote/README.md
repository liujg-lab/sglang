# CLEAR_TREE_REMOTE

`CLEAR_TREE_REMOTE` 是从 `OPT_TREE_REMOTE` 复制出来的独立算法。服务 W 和 τ 上的 K 都从平表起步：一批一个请求时 W 为 8、K 为 16，其余 W 为 4、K 为 8。在线 K 和在线 W 由 Draft 的 `SGLANG_CLEAR_LEDGER=1` 打开。验证数 K 默认在 2、4、8、16、32、64 里选，可用 `--clear-tree-ks` 改。探测轮、平表档还没有样本的轮、层样本不够的轮、非贪心轮，以及批建树失败后的回退轮，都用 τ，并且 K 锁在平表。这一档的 KV 桶装不下时退到装得下的最大档；平表档超过本轮覆盖上界时，改用上界以内最大的一档。回退轮不加轮次、不取探测、不进宽度配对，b 取整个包的请求数。τ 轮的停层按本轮锁定的 K 算质量，不是按层宽。账本开着时，服务 W 只由分段配对决定：每个 b 档（1、2–4、≥5）一段，超集比例从 20% 起。普通轮和 `probe_w` 不记样本。超集轮在当前、加宽、缩窄都有值时同时记两边，缺一档就不记；没有更窄一档时只记加宽。最宽档按 virt 只记缩窄。数到 15 用 g−2se 大于 0.5%，恰好一侧成立才换宽；两边都成立则留下样本继续探测。攒到 30 用 g−se 大于 0.5%。满 30 时只有一侧成立才换宽；两边都成立则停留并清空样本，超集比例不变；两边都不成立则停留并把比例减半，最低 5%。没有已提交文本的回放，也没有 3% 门槛。不想超过 16 时启动用 `--clear-tree-widths 2 4 8 16`。账本默认关闭；关着时不取探测，每一轮都是平表的 W 和 K，停层用 τ，质量按这个 K 算。

启动用 `--speculative-algorithm CLEAR_TREE_REMOTE` 和 `--clear-tree-role`。这些参数与 `--opt-tree-*` 分开。默认 RPC 地址是 `127.0.0.1`，端口是 `30019`。`--clear-tree-widths` 未指定时是 2 4 8 16 32 64，`--clear-tree-ks` 未指定时是同一组数。平表要求宽度里有 4 和 8、验证数里有 8 和 16，缺了拒绝启动。`--speculative-num-draft-tokens` 是图和缓冲容量：Target 为最大 K 加 1，默认 65；Draft 为最大 W，默认 64。Draft 的 bonus 缓冲是最大 K 加 1，默认 65。省略该参数时按这个容量填上；显式传入的值必须等于它。握手仍用 `--clear-tree-width`，它不是候选列表。未设置 `--max-running-requests` 时改为 48。CUDA 和 NPU 图按该进程的 batch 列表捕获，这个列表不是算法常量。启动捕获每一个候选。Target 验证图默认是 65、33、17、9、5、3，另加 decode 的 1，回放按本轮 K+1 选图。Draft 层图默认是 64、32、16、8、4、2，另加 decode 的 1。Draft bonus 预测默认开启，K+1 宽验证图按候选 K 加 1 捕获，默认是 65、33、17、9、5、3，并在每个已配置且容量允许的 batch 上捕获，与层图共用无后缀的 `r{G}_{bs}`；显式设置 `SGLANG_CLEAR_BONUS_PREDICTION=0` 关闭时不捕获这些 K+1 宽图。层宽与 K+1 宽度重合时只捕获一份。默认候选、最终 batch 列表为 1/2/4、单 stream、token 缓冲容量为 256 时，共捕获 38 张无后缀 Draft 图，其中 batch 4 的 65 宽超过容量而不捕获；图数不是算法常量。

在线 K、在线 W 和账本以本文件和本目录代码为准。[design/README.md](design/README.md) 是设计，不判断正在跑的服务。从 OPT 复制来的建树和验证细节见 [../opt_tree_remote/README.md](../opt_tree_remote/README.md)。

## Draft 回包后的 KV 补算与 bonus 预测

Draft 的 `SGLANG_CLEAR_BONUS_PREDICTION` 默认开启（未设置或设为 `1`），显式设为 `0` 可关闭。关闭时，page size 为 1、`SGLANG_CLEAR_TREE_KV_REUSE` 开启且请求可复用时，回包后仍按各请求的停止深度分组补算最后一层 KV，再发布树 KV lease；下一轮照常复用已接受路径的 KV。关闭时不保存 bonus 候选、不做最后层 bonus 专用 top-k/拷贝，也不做猜测 token 的额外前向。Target 验证后实际提交的 bonus token 不受影响，在下一轮由正常 ingest 路径处理。

默认开启的预计算行为（也可在 Draft 启动前显式设置 `SGLANG_CLEAR_BONUS_PREDICTION=1`）：在根和每个进入验证的节点处各猜一个未包含在验证子节点中的 token，提前写入其 KV 和后续 logits；命中且成为新提交尾部时可跳过该请求下一轮的 ingest 前向。此开关只控制 ClearTree Draft，独立于树 KV 复用，不修改 Target 的 K+1 验证图、协议、在线 K 或账本时间定义。按启动配置使用，修改开关后需重启 Draft，不支持运行中热切换。page size 非 1 的现有限制不变。

所有完成最后层且就绪的请求共用一个 bonus 入口，settle 完成的 lookahead 请求也参加。每个真实验证节点与根至多各产生一个候选，候选按残余路径质量 `end_rank` 排序。`finish()` 的尾部 `parent=-2` 行只在 bonus/lease 的本地元数据视图里剥离，不改变发给 Target 的 K 长度窗口、节点索引或实际树 KV 跨度；中间出现 `-2` 的非法窗口仍拒绝。

CUDA Draft 的 bonus 和层前向共用 `r{G}_{bs}`。G 从层宽和 K+1 宽度的并集里取能覆盖候选数的最小值；都不够宽时取最大可用档，由调用方拆组，不截断。batch 按共享规则补齐，并检查补齐后的 key 存在；没有可用的 key 或关闭补齐时，用实际需要的精确宽度走 eager。例如完整树 batch 1/K16 用 G17 一次前向，batch 4/K8 用 G9 一次，默认容量下 batch 4/K64 先用 G64，剩余 1 个候选再用最小层宽 G2。每组完成后按剩余请求数重新选宽，第二组可能不再包含所有请求。不同请求候选不足和最后一组仍需 padding，`keep=False` 行完成后释放，不保留为猜测。

启动时模型满足 Triton、page size 1、且注意力层没有 sliding window、量化 scale 或 sinks，则本进程的层前向和 bonus 都走 cascade，不再按层退回 extend。不满足时全部走原来的 extend。batch 1 仍保留快速模板路径，模板按请求 pool index 和 G 分别缓存，切换 K 不混用模板或 M-RoPE delta；更大的 batch 走同一条 cascade，只是没有这份模板。已执行前向后不会再次提交 fallback。cascade 直接读 ``req_to_token``，静态缓冲按启动时的最大 batch、最大层宽和最大 K+1 一次分配，不随运行时切档重新分配。切分数随捕获 batch 变小，同一张图里不变。NPU Draft 的 page128 限制不变，仍跳过 bonus，不表示已验证 NPU bonus eager。

每组 bonus 仅使用 allocator 当前空闲的 b×G 个槽位，不把可驱逐前缀 KV 算入预算；空间不足、映射越界、重复请求行或混合 SWA allocator 时停止本轮后续组，不驱逐、不拆成逐请求串行。SWA 的 `alloc()` 可能在两个子池间部分失败，所以直接跳过。lookahead 建树前尚不知道 K，bonus 开启时预估最大 K+1 的额外预算；若 singleton 只能用窄图，则保守预留完整分组含尾部 padding 的上界。此估算不是 reservation，各组仍重新检查空闲空间，前组真实猜测继续占用 KV。`bonus_ids` 与 pinned top-k 缓冲仍存 top-(W+1)，和查询宽度无关。

旧猜测在第一组开始前只释放一次。每组一次分配和映射，前向完成后清除临时映射，`kv_allocated_len` 恢复到树末尾；真实槽位脱离映射后追加交给请求持有。下一轮命中安装和未用猜测释放不变。普通失败确认设备完成后只回收当前组尚未移交槽位，保留先前成功组，仍可发布有效树；设备完成或 allocator 释放结果不明时隔离归属并停止正常复用，不冒险重复释放或强行发布。

统一计数同时覆盖单请求和批量路径：`opt_bonus_rounds` 为请求-轮尝试数，`opt_bonus_forwards` 为提交调用次数（失败可能计入），`opt_bonus_width_{G}` 为各组宽的提交次数。`opt_bonus_requests` / `opt_bonus_query_rows` / `opt_bonus_padding_rows` 为成功安装的请求-组数、查询行数和已释放 padding 行数；拆组时 requests 可以大于 rounds。`opt_bonus_graph` / `opt_bonus_eager` / `opt_bonus_unknown` 按实际前向返回标记计，不以选宽预判冒充图命中；`opt_bonus_failed` 为入口捕获的普通失败。`opt_bonus_groups_split` 为需要额外组的请求-轮数，每请求每轮只计一次。`opt_bonus_skipped` 按被跳过请求计（资源停止时计当前组），并拆出 `opt_bonus_skipped_empty` / `opt_bonus_skipped_unready`；资源跳过按组计，分别是 `opt_bonus_skipped_kv` / `opt_bonus_skipped_map` / `opt_bonus_skipped_allocator`。`opt_lease_publish_failed` 为适用 page1 发布尝试失败数，不计正常结束或非 page1 路径。`opt_bonus_hits` / `opt_ingest_zero_fwd` 语义不变。这些不是普通建树层样本，不写入层耗时拟合。

原 `opt_bonus_batch_*` 中的 forwards/requests/query_rows/padding_rows/graph/eager/unknown/failed 及资源跳过名去掉 `batch_` 后统一使用；truncated/skipped_graph 不再产生（不截断，缺图改精确 eager）。历史实验脚本和产物保留原指标，不自动重解释其结果。

CPU/mock 测试覆盖拼装、共用图 key、实际共享捕获循环、预算、padding、logits 保活与异常回收，不代表 CUDA/NPU 实机验证通过。实机应先以固定前缀/树核对 position、可见 KV、槽位及参考 logits，再检查 batch 1/2/3/4、K8/16/32/64 的前向次数与实际 graph/eager 路径；K>W、图关闭与 lookahead 单独回归。没有受控测量不能把既有回包后耗时推算当成批量版本收益；既有 bonus 开关实验的输出分叉也不因本次修改而视为解决。

## Draft 层 lookahead

`SGLANG_CLEAR_DRAFT_LOOKAHEAD=1` 打开，默认关闭，只在 CUDA、page size 1、Triton 上生效。每层的 top-k 和扩层在设备上做，下一层前向立刻发射；主机在 GPU 计算时经固定内存拷回本层、镜像整棵树、调用 `begin_layer` 并判断停层。停下的树那一层已经发射，它就是回包后本来要补算的最后一层，回包后由 `_settle_lookahead_job` 等完成、装入 bonus id 再发布树租约，不会再前向一次。

一批一个请求走 `grow_lookahead`，一批多个请求走 `grow_lookahead_many`。批量版同一层的所有在长请求合成一次前向，按 (宽度, 在长请求数) 缓存 `ForwardBatch` 模板。只有 ingest 之前的准入会建模板：一次建好 1 到整批每个请求数的模板（建立调用 `init_new`，可能同步）。层前向只查缓存、从不建立，所以建树中途和请求进出批次都不会新建。模板不绑定请求：每层用同一次固定内存拷贝送上长度、前缀、pool 行号和各请求的 M-RoPE delta（调度器算好的 CPU `[1,1]` 值），再在模板副本上换上本层的 `req_pool_indices`、`mm_inputs`、`rids` 和 M-RoPE 位置。delta 已在设备上、不是单个值，或者模板用 M-RoPE 而某个带多模态输入的请求没有 delta 时，整批在 ingest 前退回逐层路径。没有捕获图的大小记为未命中并缓存（`opt_lookahead_group_template_misses`）；带 LoRA、encoder、mamba、`input_embeds`、`token_type_ids`、ngram 嵌入或 SWA 槽位的模板不能跨请求复用，也记为未命中（另记 `opt_lookahead_group_template_unshared`）。建立时抛异常（包括 `init_new` 和 `can_run` 里抛的）不缓存，下次准入重试（`opt_lookahead_group_template_errors`），所以一个异常请求不会让这个大小此后一直未命中。只有整批大小未命中才在 ingest 前退回逐层路径；较小的大小没有模板时，那一层记 `opt_lookahead_template_fallbacks` 并走普通前向。`opt_lookahead_group_templates` 只数建成的模板。停层仍是全批联合判断，停下的请求在最后统一切到同一个 K。ingest 之前先建好或取出模板、检查 M-RoPE delta，最后才预留 KV，所以图未命中或缺 delta 不会白白驱逐。预留量是 ingest 加各层（批量为全部请求合计），不含 bonus：bonus 仍只用当前空闲槽，放不下就跳过 bonus，不让 lookahead 退回，也不为它驱逐。单请求和批量用同一套预留：先看 allocator 空闲槽；KV 复用打开时已结束请求留在 radix 缓存里（Draft 上主要是分块预填的前缀），长跑后池子会被占满，空闲槽只剩上一轮回滚归还的部分。层前向自己的 `alloc_token_slots` 本来就会按需驱逐且不同步，所以空闲不够从来不是放弃 lookahead 的理由；准入在树缓存恰好是 `RadixCache`、allocator 是 `TokenToKVPoolAllocator`，并且空闲加可驱逐够用时，在 ingest 前一次驱逐 2 倍预留量（同一个 `evict_from_tree_cache`，只摘未加锁的叶子，主机堆操作加设备索引拼接，不同步），免得层循环里一点点驱逐。真正腾出槽位时才记 `opt_lookahead_kv_evictions` 和 `opt_lookahead_kv_evicted_tokens`。多驱逐出来的余量 bonus 也可能用上，但驱逐量本身不按 bonus 算。其他缓存类型、空闲加可驱逐仍不够、驱逐本身出错（`kv evict failed`）或驱逐后仍不够时，这一轮退回逐层路径（单请求只退这一个请求，批量整批退），日志原因写出 `need`、`free` 和 `evictable`（其他缓存类型另带 `cache=not-plain-radix`，驱逐后仍不够带 `after evict`）。循环中任何异常（包括开头分配固定内存和建树状态）都会先整批同步一次设备，再逐请求把树滚回已提交长度；只有回滚成功的请求才清掉层槽记录、缩回 KV 长度。全部成功才抛可重试的 `LookaheadFallback`，再从私有拷贝的种子 logits 重新逐层生长；同步因普通原因失败、某个请求回滚抛错或设备已中毒时，这些请求的槽位和长度原样留在请求上，登记进隔离区（带 `release_error`，之后的隔离轮询不会释放），设备按中毒处理，计数 `opt_lookahead_unsettled`，并抛 `LookaheadUnsettled`（不是 `LookaheadFallback` 的子类），这一轮直接失败、不再逐层重建：批量路径的 `produce_opt_windows` 遇到它（或失败后设备已中毒）时整批回空草稿（`opt_batch_unsettled`），不再逐请求 `_clear_expand_one`；设备中毒后单请求的 `_clear_expand_one` 和批量入口（在 `grow_batch` 之前）都直接回空草稿并清掉预填尾 logits（`opt_expand_skipped_poisoned`），不消费租约、不回滚、不长树；`_clear_rollback` 对超出保留长度的回滚一律拒绝（抛错），ingest 失败时设备已中毒则不再回滚，免得拒绝把原错误盖掉；deferred 末层没跑完要弹掉时，回滚失败同样保留槽位并隔离（`opt_deferred_unsettled`），设备已中毒则不再尝试、直接保留；所以隔离区里的槽不会被任何路径再释放，发布时同样因中毒保留槽位，交给中毒清理。部分释放后失败的回滚由回滚器抛 `SRTransferUnresolved`，按设备上下文错误处理（中毒并上抛），不走隔离分支。重建或失败的轮次都在账本里标记为 `fallback`。失败尝试留下的层样本和策略记录不进层回归、Θ、c_i；另外尝试前保存的 gain 校准（`_gain_pred`、`_gain_actual`）和本轮计划的层内状态（`_raw_gain`、冻结的 K、`_cost_depth`、`_verify_quotes`，并清空分数缓存）在放弃时恢复，免得重试把同一批层再观察一遍，或让新树撞上回收的 `id(state)`；并设 `_clear_round_retried`（每个包开始时清零），宽度回放和宽度配对跳过这一轮，但不借用 `_clear_plan_fallback`，本轮已选的 W/K 不变。单请求 lookahead 同样处理。层前向在分配 KV 槽后、写入 `req_to_token` 前出错时，page 1 上这批槽当场归还 allocator（设备上下文已坏时留给中毒清理；page 大于 1 的普通层不归还，分页扩展可能落在请求已有的最后一页里，释放会误放已提交的 KV）；映射写入成功后，先给每个请求登记 `kv_allocated_len`（批量是先整批登记，再逐行复制层槽），之后的复制失败也都在回滚范围内。普通逐层分配同样先登记再复制。树已建完但随后扩展失败、立即发布或取消 deferred 任务时，共用同一个等待：先等仍在队列里的最后一层和 bonus 拷贝；普通等待异常用设备同步确认；确认完成才发布或回滚，同步也失败就按中毒处理、保留槽位不复用，请求照样暂停，立即发布这一路还会抛 `LookaheadUnsettled`。deferred 任务因请求结束等原因要丢弃最后一层时同样先确认，确认不了或回滚失败就隔离、不清账。正常 deferred 路径仍在回包后等待。层耗时样本带 `lookahead_mode`（本进程是否跑 lookahead，按 `lookahead_supported` 缓存）：lookahead 进程里没有走 lookahead 的层（准入失败后的普通层）、以及回包前最后一个 lookahead 层（`t_stop` 时还在队列里，墙钟只截到停层）只记 `d_layer` 日志，`fit=false`，不进层模型、预拟合记录和深度比；拟合文件 schema 不变。计数 `opt_lookahead_layers`、`opt_lookahead_fallbacks`、`opt_lookahead_eager_layers`、`opt_lookahead_group_templates`、`opt_layer_forwards_critical`。

`req_to_token` 每行的列数有限，写映射的核不检查列上界，越界会写进下一个请求的行。所以每棵树按自己行里剩下的列限深：剩余可放 cap 个 W 层时，这棵树的 `max_depth` 取 cap+1（至少 2），最终深度不超过 cap。lookahead 和 KV 复用推迟的最后一层都至多写这么多层（`row_max_depths`）。被限深的树带 `row_capped`，建树结束后每轮按最终的树计一次 `opt_row_depth_capped`（lookahead 退回逐层时不重复计）；有这种树的轮次不出宽度配对样本（冻结记录里 `eligible` 为假、`row_capped` 为真），因为换一个宽度行容量给的深度也不同。已知偏差：这个判断在回包后冻结时才做，计划阶段 `choose_build_width` 仍按合格轮推进超集和窄档探测的计数，所以落在行尾请求上的超集轮或 `probe_w` 会用掉名额却不出样本；只在请求离行尾不到 (max_depth−1)×W 列时发生，下一个名额照常到来，没有为此改计划阶段。lookahead 准入要求每行至少放得下第 1 层，否则这一轮整批退回逐层路径（`opt_lookahead_row_short`）。这个代价有界：放不下第 1 层意味着前缀在行宽减 W 到行宽之间，前缀每轮至少长 1，所以至多 W 轮后它的已提交长度就超过行宽、不再进建树批次；逐层路径上 cap 为 0 的树只有种子层，不前向，推迟的最后一层也跳过（`opt_row_final_skipped`），之后回滚。lookahead 准入的 KV 预留仍按 `(max_depth−1)×W` 计每棵树，不按行容量限深减少，所以快到行尾的请求会多预留、空闲加可驱逐不够时可能多驱逐或整批退回逐层；每棵树多出不超过 (max_depth−1)×W 个槽，只慢不错，没有为此改预留。每次层分配之前（单请求、批量逐层、批量 lookahead、ingest）还会再查一次，放不下就在分配前抛 `RowOverflow`（`opt_row_overflow_blocked`，正常应为 0）。已提交长度本身超过行宽的请求不预填、不长树，直接回空草稿（`opt_row_short_empty`）。它此后不会再走到租约消费，所以这时就释放上一轮留下的树租约和 bonus 猜测（设备可安全归还时），并丢掉它缓存的 lookahead decode batch（主机状态，不等设备），每个请求只打一次警告。只在 STEP 上动账本（PREFILL 只给上一轮记一个 gap，不改那一轮）：这些 rid 移出本轮的 rids、前缀长度和 b，与计划用的请求一致，价格、接受统计和层拟合照常；它们之后仍出现在包里，不算 `new_rid`。Target 的验证批次仍包含它们，所以这一轮不写 T_K 影子回归、H、Q，也不写 Θ 价格（这一轮的墙钟包含 Target 验证它们，b 却已不算它们）；`d_round` 带 `row_short_rids`，计数 `opt_row_short_rounds`。整轮都是这种请求时以 `row_short` 排除。两项已知偏差：其一，计划只看到能放下的请求，K 和 W 按较小的 b 和较短的最大前缀定价，而 Target 验证的是整包，超行宽请求的前缀最长，NPU 上常常超过最大桶而走 eager，所以这些轮次的验证成本被低估，`d_round` 的 `kv_bucket` 和 `over_bucket` 也按剩下的请求算，只作诊断。这些轮次本身不进 T_K、H、Q、Θ，错的预测不会被学进去；要修得让计划看到整包、建树只用能放下的请求，没有做。其二，超行宽请求在 Target 上会一直生成到结束，期间与它同批的每一轮都不写 T_K、H、Q 和 Θ，这些表在它的整个剩余生命周期里停在旧值上（层拟合和接受统计照常）；用 Target 报告的整包 b 写 H 会把只验证 1 个 token 的请求算成 K+1 个，系统性偏低，所以宁可暂停也不写。看 `opt_row_short_rounds` 判断影响有多大。bonus 原来就检查行宽。

单请求 lookahead 以前没有调用 `begin_layer`，开着它时下一层增益的校准不更新；现在两条路径都调用。`d_layer` 多一个 `lookahead` 字段。lookahead 实际能运行时（开关打开，且是 CUDA、page 1、Triton）Draft 拟合文件头带 `lookahead: true`，不开 lookahead 时生成的文件不会被它复用，会重新预拟合；不能运行时头里没有这个键，旧文件照常可用。批量路径在定 K 之前打 `mark_stop`，与逐层路径一致，定 K 的耗时不计入最后一层。

## PREFILL 的图片原始字节

协议版本是 2。版本 2 的 PREFILL 和快照可以带原图字节，不带像素张量；两端版本不一致时按 `protocol_mismatch` 拒绝，不会把字节当像素喂给 ViT。

Target 的 tokenizer 在 `SpeculativeAlgorithm.keeps_source_image_bytes` 为真时把每张图的原始编码字节放进 `TokenizedGenerateReqInput.source_image_bytes`，scheduler 拷到 `Req.source_image_bytes`。这个判断只在 ClearTree Target 上为真；Draft 和其他算法都不保留。data URI、裸 base64、bytes、本地路径和 `file://` 能取到字节；HTTP(S) URL、已解码图片或任何一张取不到时，这个请求整条走原来的张量。`SGLANG_CLEAR_MM_SOURCE=0`（Target）关闭，用于同一构建的对照。

发送条件不变：仍是 `requires_mm` 且特征还在。满足时，只要全部是图片、`image_grid_thw` 的行数等于图片数，就发原图字节加 Target 的条目元数据（offsets、pad_value、hash、grid），否则照旧发张量。Draft 收到后按 Target 的 grid 把每张图缩放到 `(grid_w·patch, grid_h·patch)`（BICUBIC），用自己的 image processor 在 `do_resize=False` 下出 `pixel_values`，再要求得到的 grid 与 Target 完全相同。不同或解码失败时这个请求回 REJECT 并降级为不投机，Target 照常出结果。Draft 和 Target 的缩放插值可能不同，Draft 看到的像素会有细小差别，只影响草稿，不影响输出。

计数：Target 的 `mm_source_sent`、`mm_source_bytes`；Draft 的 `mm_source_ok`、`mm_source_mismatch`、`mm_source_error`，以及 `host_mean_ms` 里的 `mm_source_decode`。这条路径只经过 ClearTree 自己的 `_pack_request` / `_unpack_request`，不改 `SRMMPayload` 和 STANDALONE_REMOTE 的传输。

## RPD 验证

只在 Target 上用 `--speculative-verify-mode rpd` 和 `--speculative-rpd-tau` 打开；Draft 传 `rpd` 拒绝启动。Target 每轮按本轮的验证数 K 建 RPD 的 host 拓扑，宽度是 K+1，不是建树宽度 W，也不读 `--clear-tree-width`。拓扑由 `clear_tree_rpd.py` 从父指针建出，没有草稿的请求整行没有边。选路、统计和验证后处理走共享的 RPD 路径，不改 STANDALONE_REMOTE 的报文。建拓扑被拒时直接报错，不退回 greedy。

Target 头的 `target_info` 带 `verify_mode`。只有 `rpd` 进入拟合文件的 Target 身份：RPD 每次验证多一次统计回传、一次事件等待和主机选路，H 比 greedy 大约多 0.7–0.8 ms（2026-11-26-a）。greedy 和 `auto` 的头没有这一键，所以加这一项之前写的文件照常匹配它们；RPD Target 写出的文件头会带 `verify_mode: "rpd"`，只匹配 RPD Target。同理，Target 在 RPD 和非 RPD 之间切换算换了 Target 头，会话推进时走头不一致的清理。RPD 下 W 和 K 照常在线，和 greedy 是同一套规则：K 探测、宽度回放和配对、按 J 选 K、按净收益停层都照旧，c 用同一个池化接受比 P。依据是 2026-11-26-b 的 `d_rpd`：在同一批请求上，RPD 的接受数与路径质量之比在 K′=2–16 各档之间只差 1.5%（b=1）和 1.3%（b=4），逐档边际 0.93–1.03 对 c≈0.97，形状与 greedy 相同。这份证据只覆盖 K′≤16，NPU 上 RPD 也只跑过 K=8 和 16；在线 K 选到 32、64 时 c 是否仍持平，要看之后 `d_rpd` 里这些档的 `accept_k`，目前不设上限。回放和配对按 `accept_ratio × 路径质量` 计接受，K 探测只补 H 样本，都不假设 greedy 接受。RPD Target 单独预拟合 H 和层耗时，拟合文件按模式分开：greedy 用 `clear_tree_fit.json`，RPD 用 `clear_tree_fit.rpd.json`（`SGLANG_CLEAR_FIT_PATH` 覆盖时同样在扩展名前插入 `.rpd`，没有扩展名就直接追加）。Draft 启动时两份都读，拿到 Target 头后按 `verify_mode` 选一份装入，预拟合也只写本模式那一份，所以来回切换模式不会覆盖另一份，也不用重扫。日志打一次 `[CLEAR] target verifies with RPD; W/K run online on fit file <path>`。旧 Target 不带这一项，按非 RPD 处理。协议版本不变。Draft 已不再回 `rpd_flat`，但 Target 仍把它当 `disabled`：两端代码分开同步，Target 新、Draft 旧时，Draft 对 RPD 头仍回 `rpd_flat` 并走平表，Target 停在 `disabled`，不会一直重试。

诊断（只记录，不参与决策）：Target 每次走主机选路的 RPD 验证后，只在 tp rank 0（发报告的那个 rank）上从 SR 的 RPD 工作区读本轮边统计，按 `_rpd_select_host` 同一规则（差值不超过 `rpd_gap_max(τ)`，τ=0 时是 token 等于父节点 argmax）给每个请求出一个可接受槽位掩码：槽位 v 可接受时置第 v−1 位，十六进制。没有草稿的请求不出；这一轮走了设备回退 `verify_tree_rpd`、或工作区已不是本轮时整份不出。掩码作为验证报告的 `rpd`，随之后的 STEP 以 `target_verify_rpd`（`rid → hex`）发给 Draft，非法项整份丢弃，协议版本不变。Draft 关账时，若匹配上的报告带掩码，`e_rid` 每个请求另记 `accept_k`、`rpd_valid` 和 `rpd_ok`：`accept_k[K′]` 是名次前 K′ 的窗口里 RPD 的接受数，等于从根起全程可接受、名次不超过 K′ 的节点的最大深度加 1。窗口按名次截取且祖先闭合，所以 K′ 不超过窗口长度时是精确值；超过时只有窗口已是整棵树才补上，否则为 null。「整棵树」指窗口覆盖了这棵树的全部 深度×W 个节点（窗口取的是前 min(K, 深度×W) 个），树恰好 K 个节点也算；不用 Target 整批的 K，Target 会把较短的行补到整批最大的 K。`rpd_valid` 是可接受槽位数，`rpd_ok` 表示整窗口的值等于实际接受数，为假说明槽位没对上，这一行不要用。`d_round` 的 `rpd_masks` 是本轮掩码算出了 `accept_k` 的请求数，没有掩码时为 null。实际运行里掩码几乎总是晚到：Target 在验证内部接受完成后就发出下一个 STEP（共享的 accept-ready hook），这一轮的报告在那之后才存好，所以第 r 轮的报告随 STEP r+2 到达，Draft 已在 STEP r+1 关掉第 r 轮，这时 `d_round` 里没有掩码（2026-11-26-a 全部如此）。为此 Draft 关账时若没对上报告，就留住本轮每个请求的树、接受数和 `mass_k`（最多最近 `LATE_RPD_ROUNDS`=8 轮，换会话或清理待配对报告时丢弃）；之后带 `rpd` 的报告点名到这一轮，就另打一行 `[CLEAR ledger d_rpd]`：`session_id`、`rpc_seq`（与该轮 `d_round` 相同）、`b`、`k`、`w`、该轮的 `excluded`、`e_pred`、`e_mass`、`rpd_masks`，以及 `e_rid`（只含有掩码的请求，每行 `depth`、`accepted`、`mass_k`、`accept_k`、`rpd_valid`、`rpd_ok`，口径与关账时对上的一样）。H/Q 照旧走暂存配对，不受影响。Target `t_verify` 里的 `rpc_seq` 是验证中途发出的下一个 STEP 的编号，比报告和 `d_round` 大 1，不要拿它对齐。`test/manual/clear_rpd_accept_curve.py <draft.log>` 同时读 `d_round` 和 `d_rpd`，按 b 档和 K′ 汇总 r(K′) = ΣA/Σmass_k，与本轮服务用的 c（Σe_pred/Σe_mass，默认池化时就是 P）对比。大档只在整棵树窗口的浅树上有值，所以全量表各档不可比；结论只看「匹配集」：从小档起逐个加档，只要同时有这些档的请求不少于 `--min-n`（默认 30）且不少于全部请求的 `--min-share`（默认一半），就在这同一批请求上比较 r(K′)，各档之差小于 5% 时一个池化 c 足以吸收 RPD，否则需要按 K 分档的 c_K。

模式切换：池化接受比 P 不按模式分池。新 Target 头的 `verify_mode` 与上一个头不同（greedy/`auto` 与 `rpd` 之间）时，头不一致的清理之外再清掉 P、Θ、c_i、各 batch 档的服务宽度和回放状态，等同于重启 Draft，只保留层拟合和 H 文件的选取；日志打一次 `[CLEAR] target verify mode changed <旧> -> <新>; ...`。同一模式下换 Target（或第一次拿到头）不清。CPU 测试只覆盖拓扑宽度、τ=0 与 greedy 一致、RPD 下在线 W/K 与 greedy 同计划和拟合文件按模式分开，不代表 CUDA/NPU 实机验证通过；NPU 上 RPD 目前只跑过 K=8 和 16。

## 账本

在线 K 和在线 W 由 Draft 的 `SGLANG_CLEAR_LEDGER=1` 打开。Target 的账本只记自己的日志，不参与选 K。默认关闭。只在 tp rank 0 输出。Draft `tp_size > 1` 直接拒绝启动：账本和样本只在 rank 0，其他 rank 会另走一套 τ。

账本开着时，Draft 记录时间账本和每次层前向，并拟合层耗时。干净轮（进 Θ 的轮）同时更新各 b 的 seed EMA，供宽度配对使用。层回归按 (W, path, 图档) 分开，特征是截距和前缀之和，岭是截距 0、前缀之和 128²；每个新样本先把整份矩阵乘 0.999 再累加。装入拟合（预拟合提交或读拟合文件）时，每个能解出的格子把预拟合斜率 β1_p 和它的斜率信息量 S_p = xtx11 − xtx01²/xtx00 冻结成先验：求解时前缀之和一项在 128² 之外再加 S_p，右端加 S_p·β1_p；β1_p 就是装入时的解，所以装入那一刻预测不变。先验不随遗忘衰减，不设上限；截距没有先验，水平只由在线样本决定；预拟合矩阵仍作为在线部分的初值随遗忘淡出。没有装入拟合的格子仍用原来的岭。日志 `[CLEAR] layer slope priors installed cells=N`。`SGLANG_CLEAR_LAYER_SLOPE_PRIOR=0` 关掉先验，用于同一构建的对照；图档是实际回放的捕获 batch；前缀范围检查按格子各自统计。捕图列表是 1/2/4 时，新旧口径一致；列表含 3 时，active=3 记成 3。查询的前缀之和比见过的最小或最大再超出 max(128, 这段跨度)，或者预测不大于 0 时，这一档没有层耗时。服务宽度因此走平表，这一档在宽度配对里不出样本。层拟合够样本后，停层用同一个 `J_K`：人数从 1 枚举到还能再长的请求数，只保留继续价值更大的那一组。平表档有样本以后，K 在不超过覆盖上界、并且这一格自己有样本的档里取 `J_K` 最大的一档。覆盖上界是装得下本轮建树宽度乘以 max_depth 减 1 个节点的最小档，选 K 时再收到各请求的实际节点数。普通轮按服务宽度建树；超集轮按相邻更宽一档建树。层耗时和选 K 的覆盖都用这一轮实际要建的宽度。平表档超过这个上界时，改用上界以内最大的一档。平表档还没有样本、正在做 K 探测、或者非贪心时仍用 τ，K 锁平表；只有非平表档有样本时不取探测。平表档有样本之后才探别的档，跳过平表档，离它最近的先探，每档 2 个样本。探测上界是本轮建树宽度的覆盖档。探测轮数达到 max(2 × K 的档数, 已过轮数 / 20) 后不再取探测，这一格停在已有样本的档上继续在线选 K。Target 把已经完成的 `device_us` 放进下一轮 ClearTree 请求的 `verify_samples`。这条字段不属于 STANDALONE_REMOTE。Draft 解析它并打日志，不再写入选 K 用的验证表。Target 在验证开始时冻结 session、回包序号、b、K 和验证前长度，桶用冻结长度加 K 再加 1。报告可以晚于关闭该轮的 STEP，挂在之后的 STEP 上，序号仍是这份冻结值。字段是 `target_verify_rpc_seq`、`target_verify_b`、`target_verify_k`、`target_verify_bucket`、`target_verify_path` 和 `target_verify_fallback`。`path` 是 `graph`、`eager` 或 `fallback`。只有没使用草稿才是 `fallback`。eager 不写 H/Q，也不排除整轮。超桶不写 H/Q。能拆分的会话只用 `graph` 且有桶的报告给 H 和 Q 贴标签，不用 Draft 计划里的 K 和桶。关账时没有匹配报告就把 H/Q 按 `(session, rpc_seq)` 暂存，后到的报告按同一键合并；提交前再合并一次。仍没有报告的轮不写。写表日志带实际的 rpc、b、K、桶和 path。会话切换或超过 64 条未配对记录时丢掉旧项。验证表在轮次关闭时写入 Draft 的 `T_K`，托底轮也写。`SGLANG_CLEAR_LOCK_K=32` 把验证数锁在 32，停层仍用 τ，并且不消耗探测。批建树失败后的回退轮同样是 τ 加平表 K，排除原因含 `fallback`，不进 Θ、c_i、层回归、验证表和宽度配对。

- `SGLANG_CLEAR_TARGET_BACKEND` 不决定选 K。CUDA 和 NPU Target 都用 Draft 的 `T_K`。`cuda`（默认）时 Draft 仍用 `T_K` 拟合只写日志的影子回归；`npu` 时这条影子回归不更新。Target 自己的 `device_us` 回归只留在 Target 进程。
- `SGLANG_CLEAR_NPU_KV_BUCKETS`：Draft 计算 KV 桶用的列表，逗号分隔。默认 `256,512,1024,2048,4096`。
- Target 的 `t_verify` 用 `SGLANG_NPU_TREE_GRAPH_KV_BUCKETS`（未设置时用同一组默认桶）和 `select_tree_kv_bucket`。超出最大桶记为 eager。事件当时完成时，`device_us` 只在 `[CLEAR ledger t_verify]` 里，不再另打一行。事件未完成时，下一次 poll 补记 `[CLEAR ledger t_verify_device]` 并更新同一条回归。没有 `t_verify_device` 不表示没记到验证耗时。
- `t_verify` 还记 Target 主机侧各段墙钟（微秒，只记日志，不进任何拟合）：`verify_wall_us` 是整次 ClearTree verify（含前向）；`accept_ready_us` 是从 verify 开始到共享 accept-ready hook 发出下一个 STEP 之前，即这次验证落在 Draft 的 H 里的部分；RPD 时另记 `rpd_build_us`（建验证输入时的拓扑构建和边索引上传，在 verify 开始之前，也在 H 里）、`rpd_stats_us`（边统计、D2H 拷贝和等前向完成，所以含前向的设备尾段）、`rpd_select_us`（统计之后的主机选路）和 `rpd_mask_us`（可接受槽位掩码，在下一个 STEP 发出之后，不在 H 里）。ClearTree Target 把 SR 的 RPD 工作区换成一个只加时间戳的子类，结果、计数和共享代码都不变。这一次走了设备回退或不是 RPD 时，RPD 各段为 null；非 RPD 时 `rpd_*` 全为 null，前两项照常记，用于和 greedy 对比。判断 RPD 的 H 增量落在哪里，用同一 (b, K, 桶) 下 RPD 与 greedy 的 `accept_ready_us` 之差加上 `rpd_build_us`，与 Draft 的 H 之差对照。

接受比 c_i 把路径质量换算成预期接受数，乘进停层和选 K 的 `J_K`、宽度回放的 E 和 `d_round` 的 `e_pred`。关账时用下一包的提交长度结算上一轮：接受数是前缀增长减 1（扣掉 bonus），路径质量是核验节点的路径分数之和。默认所有请求共用一个池化比值 P = (ΣA + 3)/(ΣE + 3)，3 是值为 1 的先验质量，开头一两轮没有接受时 P 不会掉到 0。池化累计按路径质量遗忘：每结算质量 m，旧的 ΣA、ΣE 先乘 0.5^(m/半衰期)，所以批量轮按自己的质量老化，不按轮数。半衰期默认 1000 个质量单位（并发 1 约 300 轮），用 `SGLANG_CLEAR_ACCEPT_HALF_LIFE` 改，0 或负数不遗忘，非数字保留默认。`SGLANG_CLEAR_ACCEPT_PER_REQUEST=1` 恢复逐请求收缩 c_i = (A_i + 3P)/(E_i + 3)，用于同一构建的对照；逐请求累计不遗忘，请求结束时丢掉。和旧行为相比，P 多了先验和遗忘；`SGLANG_CLEAR_ACCEPT_HALF_LIFE=0` 时只差先验。改成池化的依据是 RSTeller 和 WaterCaption 并发 1 的实测：各请求比值的离散只有抽样噪声大小，同一请求前后半段的比值不相关，逐请求收缩的每轮接受数误差比纯池化高 4% 到 6%，在 RSTeller 上还整体偏低约 9%。按实测轮序列回放：不遗忘时，负载从 RSTeller 切到 WaterCaption 后 P 偏低 3%，把接受率人为降到 0.6 倍的切换里偏高 47%；半衰期 1000 把两者压到 4% 以内，平稳时误差多不到 0.2%；半衰期 300 时平稳误差多 0.4% 到 0.8%。预拟合轮、回退轮和 `target_gap` 轮仍不进 P。

Draft 在回包后冻结本轮的树。合格轮立刻按分段配对记样本，段末才可能换服务宽度，然后输出暂存的 `d_round`、`d_layer`，以及段末的 `d_wpair`。空闲轮也输出已生成的日志。换宽从下一棵树生效。消息格式不变，Target 日志仍即时输出。冻结时每一层行按这一层实际前向过的树查价：建树结束、入队回放前按 `(cached_len − prefix_len) / W` 给每棵树记 `forwarded_layers`。lookahead 在判停前发射第 d 层，所以停在 d 的树也算在第 d 行里；逐层路径只算还要再长的树（没有这个字段时也按此口径，即深度减 1）。行数仍是最深那棵树的深度减 1，lookahead 最后一次发射不在关键路径上，不计。KV 不够时逐层路径拆成的多个小批，仍按一批查价。

`policy_ms`，收包时间记在新开的那一轮。上一轮的关账（拆 H/Q、写 H 和 Q、层回归、θ、c_i 结算、组装 `d_round`）默认推迟到本轮回包发出之后、`run_post_reply` 之前执行，所以 `policy_recv_ms` 不含关账，Target 也不等它。收包时把已关的轮、待结算的 c_i 路径质量和当时的增益比一起摘下，本轮建树写入的新路径质量不会混进上一轮的结算；最新一条 H、Q、θ、c_i 和层样本因此晚一轮才参与决策。会话号变化时仍在收包时同步关账。下一个包、空闲刷日志和会话推进之前都会先补做没做完的关账。`d_round` 另有 `close_ms`（这次关账的耗时）和 `close_deferred`（是否推迟）；推迟时 `wait_ms` 会少掉 时间口径不同）。层回归被整体替换（装入拟合）时清空这些比值，因为它们是相对被替换的回归测得的。`(W, g, 深度)` 满 30 个样本用自己的比值，否则用同一 `g`、同一深度合并各宽度的比值，再不够取 1。停层判断按要前向的那一层（等于当前树深）取比值，宽度回放第 i 行取深度 i+1；不传深度的调用（计划宽度、超集就绪、窄档定价）不变。停层判断在同一轮里按 (活跃请求数, 深度) 缓存比值，只查一次。`SGLANG_CLEAR_LAYER_DEPTH=0` 只学习不使用。`d_layer` 另有 `last`、`depth_ratio`、`depth_src`：`depth_ratio` 是该样本的 (W, g, 深度) 在本次学习之前已经学到的比值，开关关闭时照常记录但预测没有使用，所以两种模式下 `pred_ms × depth_ratio` 是被接受路径上各节点在全树验证顺序里的名次（从 1 起，顺序与切窗口相同：分数降序，再深度升序、列升序），窗口就是名次 1 到 K。路径分数沿边不增、同分浅层优先，所以名次沿路径严格递增，温度 0 下任一更小的 K′ 的接受数就是名次不超过 K′ 的个数，在 greedy 验证下这是精确的。RPD 选的是可接受路径里最长的一条，窗口变小可能换成另一条分支，这个计数只是下界（2026-11-26-b 为空、`path_ok` 为假，`depth` 和 `accepted` 照常。`k_mode` 说明本轮 K 怎么定：`value` 是按 J 选的，`tau`、`probe`、`locked`、`fallback`、`prefit` 的 K 是固定的。只有 `value` 轮记 `verify_quotes`（本轮决策已经报过价的 H+Q，只含不超过 `k_cover`
