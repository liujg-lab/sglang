# ClearTree 验证计划

算法设计见 [../README.md](../README.md)（当前为第十版；第九版见 [../design_v9.md](../design_v9.md)），实验通用约定见 README 的"实验约定"。验证要回答四个问题：

1. **值不值得做：** 网络和 batch 变化时，"每格调到最好"比"最好的一套静态配置加自适应开关"高多少（前置测量）。
2. **概率模型对不对：** 校准后的接受概率在新请求、深层、前 K 截断线附近是否可靠（阶段 1）。
3. **快照预测对不对：** 快照库能否预测下一层的 ΔG（阶段 2）。
4. **规划有没有用：** 预测误差和规划开销最终是否转化成真实吞吐（阶段 3–5）。

合成模拟已经给出了这些问题的先验（[results.md](results.md) 第 7 节）：收益主要在 b≥4，规划器必须编译实现，统计决策层和快照库的选择偏差处理在模拟里没有可测的收益。第 6 轮（7.7 节）还显示：成本表的上下文、K_g 沿用和 δ 衰减对吞吐的影响都在 1% 以内；开关的计时口径会造成最多 5.5% 的损失；停止边界附近偏差主要来自校准，但后悔很小。实测要确认或推翻这些结论，判断时看后悔或吞吐影响，不只看偏差比例。

**第十版（2026-11-10，设计文档"算法（第十版）"，D52–D56）改变了验证重点：**
- 合成模拟第 7–11 轮之后，第一版改成"层宽和验证数解耦 + 每层按整批算账 + Θ 按 b 分开 + b>1 才启用的开关"。不再需要 GLMM、快照库、子集 DP、K_g/K_v、C++ 规划器。
- 所以阶段 1、2（检验 GLMM 和快照库）不再阻塞实现，改为第十版第七小节"第二步模块"的触发条件检查。
- 现在最关键的实测有三项：
  - **V2：** 每个 (b, K) 档的验证耗时，按实际形状测（每个请求 33 个验证位置、b=1 最先测），包括补齐、图路径和 eager 路径、前缀长度；只看总 token 数不能判断是不是插值（D57）。要测的是所有随 K 变化的关键路径时间，包括 Target kernel、K+1 个 token 和父指针的传输、两端打包、Target 调度，不只 kernel（D59）。按时间账本取 T_K = (t_send − t_stop) + (t_recv − t_send) 在不同 K 之间的差，只看"回包到下一条 STEP"会漏掉 Draft 端回包前的选点、KV 收尾和序列化；同时报告"Draft 托底"轮次的占比（D60）。这张表直接被选 K 和生长的同一口径用到（D58、D59）。各 K 档之间如果有明显台阶，"直接预测下一层"的模块优先级要提高（合成：一步滞后的代价 +0.5% 到 +2.0%，D60）。
  - **层耗时微基准：** 每个 (图档 1、2、4、8, W 2、4、8) 的 Draft 层耗时，只算层前向。这张表用来定 W 表，也被回放审计用到；在线学的层成本模型对没跑过的宽度会外推出错（合成 b=1 低估约 30%）。还要测同一图档内的混合前缀组合，检查引理 A 的前提（D60）。
  - **V7：** 2–3 个数据集上的扫参，同时记录首位 top-1 命中率，用来定"接受率高"的阈值和 (W, K) 表。
  - **E2′：** 用停止边界审计按深度检查"实际增量 / ĝ"（边际校准），实际增量要算上被挤出验证集的节点；退出审计估计错误退出的损失。另外用同树回放算按档位段的 f（跨 K 的边际，所有 K 上都算），和同一棵树上预测的差、实际的差；某段 f 持续偏离 1 超过 15% 才考虑 f_band（D60）。

**D60（审稿意见 16、合成第 17 轮）带来的其他变化：**
- 漂移检测看不到没在用的 K 变便宜，所以阶段 3 要验证事件触发的全档重测，短测量改成随机交错。
- 回放审计不了"停得太早"，评估阶段用加深探索（约 1% 的轮次停下后多长 2 层）估计停早和跨 K 停止的损失。
- Θ_b 定为纯解码价格：Draft 自己的 PREFILL 时段扣掉，Target 端的 PREFILL 和空闲整轮丢弃并记录；实测后比较"扣时段"和"丢整轮"两种估计。

**原则：** 第一版只实现第十版；第二步模块（第九版的部分）按设计文档第十版第七小节的触发条件逐个加，不预先实现。

### 3.1 FINISH 带最后一轮的 token（SR 共享协议改动，D51）

**状态：** 2026-11-10 用户决定做，这里只是方案，代码没有写。这是插桩规则"不改 SR 共享代码"的唯一例外。

**目的：** 请求在某一轮结束时，Draft 收不到下一条 STEP。于是这一轮的标签、提交数，以及 OPT 的接受深度计数都会缺一轮。FINISH 带上这一轮提交的 token 后，Draft 可以像普通轮一样结算。

**核对过的代码事实（只读了代码，没有运行）：**
- **FINISH 现在只带三样：** rid、step_id、base_committed_len，见 `sr_target_scheduler_mixin.py` 的 `_build_sr_request`。它要等在途 STEP 的回包被取走后才发（`_sr_flush_finish_notifications`），而且只发不等回包（`sr_transport.py`）。
- **不能复用现有的 delta 字段。** FINISH/ABORT 上只要出现 `commit_mode`、`committed_ids`、`padded_input_ids`、`sampling_params`、`delta_ids`、`base_commit_version`、`base_output_len` 中的任何一个，Draft 的 `structural_error`（`sr_commit.py`）就返回 `commit_on_control`，整条 FINISH 被 REJECT。结果是 `_sr_finish_rid` 不执行，请求的 KV 不释放。旧版 Draft 同样如此。
- **新增可选字段对旧 Draft 无害：** 编码是 `pickle(to_dict())`，`SRDraftRequest.from_dict` 会丢掉不认识的键。
- **两端都已有可用的状态：**
  - Target：`req.sr_ack_output_len` 是 Draft 已确认的输出长度，收到回包时更新。
  - Draft：`SRDraftState` 有 `acked_output_ids` 和 `cached_reply`。后者存着上一棵树的 token、parent_list、tree_version、ack_output_len，都在 host 上。
- **output_ids 截止在结束处：** 接受循环每 append 一个 token 就调一次 `check_finished`，结束后不再追加（`sr_worker.py`、`sr_fixed_accept.py`）。所以 output_ids 停在 stop token 或 max_new_tokens 处。
- **影响范围：**
  - OPT 的 Target 也经 `notify_sr_draft_finished` 发 FINISH。
  - OPT 的 Draft 用自己的 `_opt_handle_batch_impl`，但逐个请求仍调用 `_sr_prepare_v2`。
  - TOLL 有自己的协议，SPECTRE 不走 SR 协议，两者都不受影响。

**协议：** `SRDraftRequest` 新增三个可选字段，只在 FINISH 上出现。协议版本号仍为 2。

| 字段 | 含义 | Target 的取值 |
|---|---|---|
| `finish_base_output_len` | 尾部的起点，用输出坐标（不含 prompt） | `req.sr_ack_output_len`。从没收到过确认（`sr_ack_commit_version` 为空）时，三个字段都不发 |
| `finish_tail_ids` | 起点之后提交的全部 token | `output_ids[finish_base_output_len:]`。长度超过一轮最多能提交的数（`speculative_num_steps + 1`）时三个字段都不发，因为这说明两次确认之间隔了不止一轮 |
| `finish_tree_version` | 最后一轮验证的是哪一棵树 | 最后一轮确实验证了 `sr_draft_tree_version` 那棵树时才发；AR 回退、空草稿时不发。验证后这个字段能否保留到 FINISH 发出时，实现时要核实 |

- **用输出坐标，不用 base_committed_len 推算：** Draft 压缩视觉 prompt 时（`draft_prompt_len`），两端的 prompt 长度不同。
- **只在 FINISH 上出现：** ABORT 不带。STEP 或 PREFILL 上出现这些字段时，Draft 忽略并计数，不 REJECT。
- **开关：** Target 端用 `SGLANG_SR_FINISH_TAIL`（默认 1）。关掉后和现在完全一样，用于 A/B 对比和出问题时回退。
- **对其他机制没有影响：** FINISH 只发不收，所以超时和熔断都不受影响。投机停止或熔断打开时，FINISH 照常发出；这时已确认长度通常已经落后很多，尾部会因超长而不发，或者标成 `unverified`。

**兼容性：**

| Target | Draft | 结果 |
|---|---|---|
| 新 | 旧 | 旧 Draft 丢掉新键，FINISH 照常释放 |
| 旧 | 新 | 没有尾部，计为 `absent`，行为和现在一样 |
| 新 | 新 | 带尾部 |

**Draft 端处理：**
- **位置：** 在 `_sr_prepare_v2` 处理 FINISH 时，放在 `_sr_deferred_step_gate` 和 `inspect_commit` 之前。SR 和 OPT 都会经过这里。会话清理、TTL、`_sr_wipe_all` 直接调用 `_sr_finish_rid`，不经过这里，所以没有尾部。
- **只读、不影响释放：** 只读 host 数据（`acked_output_ids`、`cached_reply`），不碰设备，不分配内存。整个处理包在 try 里，任何失败都只计数。**FINISH 的释放、延迟释放、隔离都和尾部无关。**
- **去重：** 同一个 (session, rid, step_id) 的 FINISH 只处理一次，覆盖重复 FINISH 和延迟队列合并两种情况。
- **校验：** 按下表顺序判定，结果计入 `sr_finish_tail_<结果>`。

| 结果 | 条件 |
|---|---|
| `absent` | 没有这些字段 |
| `malformed` | 不是整数列表，或长度超过本地的 `num_steps + 1` |
| `no_state`、`degraded` | 请求状态不存在，或已降级 |
| `misaligned` | `finish_base_output_len ≠ len(acked_output_ids)`，或和 `cached_reply.ack_output_len` 不同 |
| `unverified` | 位置对齐，但 `finish_tree_version` 缺失或和 `cached_reply.tree_version` 不同；只能用来结算提交数 |
| `ok` | 以上都不是 |

- **钩子：** 校验结果交给一个空钩子 `on_sr_finish_tail(state, tail)`。SR 默认只计数；OPT 和 ClearTree 的插桩各自在 `opt_tree_remote/` 里覆盖它，算法逻辑不放进 SR 目录。

**消费方怎么用（不属于这次改动）：**
- **标签：**
  - 从上一棵树的根开始，沿尾部逐个匹配，得到被接受路径 a1..aj。
  - 截断只会丢掉后面的 token，不会改已有的 token，所以尾部里每个 token 都是 Target 在该位置的 greedy 结果。尾部覆盖到的每个位置都能打标签，包括 aj 后面那个 bonus。
  - 唯一的例外：尾部恰好停在被接受路径内部，即在某个被接受节点上命中了 stop 或 max_new_tokens。这时这个节点的孩子没有 y*，记为删失，不算拒绝。
  - 这条规则只看结构，不需要知道请求为什么结束。
- **提交数：** 等于 `len(finish_tail_ids)`。字段缺失时退回旧算法：base_committed_len 减去 Target 坐标下的 prompt 长度，再减去已确认长度。
- **OPT 的最后一棵树：** `opt_accept_depth_*` 现在永远漏掉每个请求的最后一棵树，有了尾部就能补上。这属于 OPT 自己的改动，另行决定。
- **NPU 更新重叠：** 开启 Target 更新重叠时，要核实 FINISH 之前是否已经发出过带最后一轮 token 的 STEP。如果发过，尾部为空，最后一轮的标签已经由那条 STEP 带到，消费方按树版本去重即可。

**实现时要改的文件：**

## 7. 阶段 1：概率模型（E2）

| 训练样本 | M1（只用被接受父节点）、M2（全部验证过的父节点）、M3（加 off-path 指示 o_v）、M4（第二段也加 o_v） | 在留出的被接受父节点上：按（深度、排名档）的校准、每棵树 Σπ̄ 对实际接受数的偏差、边界附近的误判率。用 M3/M4 的条件：off-path 效应的整个置信区间在 ±0.1 logit 内，第二段 top-1 份额变化在 ±1 个百分点内 |
| 命题 4 的检验 | 普通 M1 GLMM 对比含选择机制的完整似然 | 两者一致，说明选择可以忽略；不一致时检查是否有按结果丢标签 |
| 拟合方法 | 拉普拉斯近似、数值积分、PQL | 截距和 σ_δ 的差异 |
| 兄弟分配 | β=1、在线学习的 β、按深度的 β_d、加形状特征 | 多分类 log loss、命中后的 top-1 准确率；够用就不加更复杂的 |
| 随位置变化的 δ | 静态 δ、按已提交位置 0.9 衰减加权的 δ、更短或更长的衰减；命题 4 的检验只在静态模型上做 | 校准误差；相邻轮接受率残差的自相关 |
| 特征缺失 | 随机抽取的审计轮做额外前向；按（深度 × 是否最后一层 × 平台 × KV 复用 × 难度档）算每个分层需要的最少样本（TOST，功效 80%） | 缺失与否和命中是否独立 |
| GLMM 残差 | 按 b、K、Σℓ 档、执行路径、dtype/TP、深度分组 | 某个维度显著时加进截距 |
| 可靠性 | 按 (d, W, w, 上下文) 分格，π̄ 对比实际接受结果；`d_stop` 的 dA/dG（被停下的请求） | Brier、log loss、ECE；**重点看决策子群**：前 K 截断线附近、深度 ≥ 3、停止边界。合成里停止边界的校准偏差 b≤2 时 23–40%，但后悔 ≤ 1.5%，所以同时报告后悔 |

**通过标准（初值）：** 决策子群里每个深度的校准误差 ≤ 5%；新请求的路径概率误差 ≤ 10%。

## 8. 阶段 2：快照预测（E1）

**数据：** V2、V3c 的 `d_snapshot`。按请求或 session 切分训练集和测试集。

| 实验 | 内容 | 指标 |
|---|---|---|
| 下一层预测 | μ̂ 对比实际 ΔG；快照次数 4、8、16；按请求缓存对比按 φ 的 kNN | 偏差和 MAE；目标偏差 ≤ 5% |

## 10. 阶段 3：求解的系数（E3）

| 实验 | 内容 | 指标 |
|---|---|---|
| Θ* | EMA 对比滚动 200 轮的吞吐；V3b 的 b 变化 | 稳态误差 ≤ 3%；b 变化后 ≤ 30 轮收敛 |
| 成本裕量 | f_D ∈ {1.0, 1.15, 1.3}，按 b 档分开 | 吞吐；模拟里 b≥4 时 1.15 多 0.7–1.6%，b=1 时 1.0 最好 |
| 成本模型 | EMA 表对比锚定的水平 + 差值；用 Target 的四个时间戳离线分解出各 K 的真实验证成本，算选 K 的不一致比例和损失；RTT 用代理切换 | 合成：不一致 37–41% 但吞吐损失 ≤ 0.84%；实测损失 > 1% 时换锚定版本 |
| K_g 重选间隔 | 每 1、5、10、20 轮；每 10 轮加上下文变化时立即重选 | 吞吐和规划开销；合成里都在 ±0.7% 内 |
| 强制 K 比例 | 1%、3%、5% | 各 K 等待时间估计的误差、Θ_探索 的损失 |
| 主方案对比 | 验证用 K_g、重选 K_v、固定 K_g、MPC-Free | 吞吐、K_v ≠ K_g 的比例 |
| 是否需要统计决策层 | 记录每层的 V_P 和决策；事后用更多快照重估同一方案（监控用，不参与决策） | 只看点估计时，误判造成的损失 > 1% 才在第二步加统计决策层 |
| 第十版：Θ_b 的估计方法（D60） | 用两端日志离线算"扣时段"的 Θ_b（只扣 Target 端 PREFILL 和空闲的那段时间），和第一版"丢整轮"的 Θ_b 比；另跑一个"价格里包含混合调度开销"的对照组 | 两种估计相差超过 1–2% 时，考虑让 STEP 带 Target 的非解码时长（SR 协议改动，需要确认）；对照组预期树偏深、吞吐更低 |
| 第十版：事件触发的全档重测（D60） | 重启 Target、重新捕获图之后，比较重测前后的 T_verify 表；短测量随机交错 8 组 | 重测前后各档差别超过 max(2 ms, 10%) 的比例；第二版漂移检测在同样的事件后是否触发 |
| 第十版：停早审计（D60） | 加深探索，约 1% 的轮次停下后多长 2 层；回放算停在 d、d+1、d+2 层时各 K 的配对吞吐 | 估计"停得太早"和跨 K 停止的损失；> 1% 时重新考虑多层前瞻（合成：跨 K 停止的价值 < 0.04%）；探索代价预计约 0.2% |
| 第十版：f_band（D60，只在 E2′ 触发时） | 和第十版配对 A/B，A B A B 交替 | 吞吐差超过 max(A/A 带宽, 1%) 才保留（合成：只有低接受率、b=1、验证 ×10 那一格 +2.4 个百分点） |

## 11. 阶段 4：开销和成本形式

| 实验 | 指标 |
|---|---|
| C++ 规划器在 Draft 进程里 | 每次决策的耗时（从这一层的 top-C 回到 host 起，到下一次层前向发出为止），P50、P95、P99、最大值，超预算比例；模拟里 V8 移植版为 9–228 µs |
| ΔT_K 的形式 | 给定 K，按 (真实节点数, 占位数, 深度分布, Σℓ, b) 分箱的等价性检验，决定第九版设计（[../design_v9.md](../design_v9.md)）三.6 的方案 A、B 还是 C |
| KV 审计 | 记账预留对比实际占用；不出现 OOM；前缀缓存的驱逐次数开、关 ClearTree 时是否变化 |
| 补算前向 | 收到 STEP 时的排队延迟，即补算前向的关键路径成本；提前退出的请求按深度多一次补算后，是否仍在等 Target 的时间里完成 |
| N_param | 1（plug-in）对比 8（按路径对 δ 积分）的规划耗时和吞吐 | 合成：积分平均 −0.21%，没有可测收益 |
| 后台维护 | GLMM 重新拟合进程开、关时的吞吐差 |

**预算：** 每次决策 P99 ≤ 0.1 ms；超出时先减少快照次数，再考虑晚一层决策。
