# ClearTree 相关测试结果

第 1–6 节的数据都在 `OPT_TREE_REMOTE` 上实测，是 ClearTree 的建模依据。第 7 节是合成模拟，不是实测。

数字来自用户在实验机上的运行，原始文件在实验目录的 `t0-run/`、`t0-run/gate/` 和 `raw/gate-window/` 下。除非另写，吞吐是两次重复的均值，单位 tok/s。

**共同配置：**
- Target：Qwen3-VL-32B，NPU 910c 两张卡，tp=2，page 128，`tree_paged_fia`，bf16，没有量化。
- Draft：Qwen3-VL-2B INT8，RTX 3090，page 1，Triton；图捕获 bs 1、2、4、8。
- 采样：temperature 0，`max_new_tokens=256`。
- 网络：单实验室内的 SSH 隧道，RTT 3–5 ms。

## 5. 4096 输出分叉的排查（`raw/gate-window/fork/`）

**现象：**
- D1（8 条前缀重复到 32，b=4）：投机 89.46，Target-only 104.76 / 104.83；差距 > 1 nat 的分叉 1 处（5.25 nat）。
- D2（32 条不同前缀，b=4）：投机 75.21，Target-only 98.80；差距 > 1 nat 的分叉 2 处（1.19 和 1.50 nat）。
- D3（b=1）：投机 42.15，Target-only 27.64。有一条前缀四次都在 t=72 写成 56056，Target-only 是 656，领先 6.81 nat。
- D4：这一轮 b=1 的验证 top-1/top-2 是 56056/5443，差 0.25 nat；b=4 时是 656/671，差 8.0 nat。两次的 KV 长度是 4172 和 4171，轮次切分差一位。

**逐项排除（同一条前缀，b=1，触发在 kv_len=4172）：**

| 嫌疑 | 结果 |
|---|---|
| 关闭 update overlap（S2） | 仍是 56056 |
| 退回 compact FIA（S1） | 252 MiB 工作区分配失败，请求退出，无结论 |
| 冷缓存 | 仍是 56056 |
| 惩罚 | 没有开启；惩罚前 top-1 就是 56056（logit 18.0 对 17.75） |
| h 父链、i/i′ 掩码、f 页内槽 | 都通过 |
| e/e2 写入槽和读取槽 | `out_cache_loc` 等于 `req_to_token[pool, 4163:4172]`，9 个槽互不相同；写入值和 cache 逐位相同 |
| j 第 0 层 V | 最大差 2⁻¹² 和 2⁻¹¹，是 bf16 噪声 |
| k/k′ 逐层 FIA | 64 层、两个 rank，和 fp32 GQA 的余弦 ≥ 0.9999 |
| 已提交前缀 4096..4166 的深层 K/V | 在 decode 对照的噪声内 |
| 量化（m3） | 没有量化，bf16 `UnquantizedLinearMethod` |
| 行耦合（m2） | M=1 单独重算和批量第 4 行逐位相同 |
| 子层局部误差（m1） | 第 30–45 层 8 个子层，投机最大 0.00366，decode 最大 0.00376 |
| 位置和树形（m4） | positions[4]=4167，cos/sin 逐位相同；这一轮是一条链 |

**残差：** 槽 0–3 的 64 层都在对照内。槽 4 从第 36 层起偏大，第 42 层相对范数 0.163（对照 0.054），第 43 层 0.333（对照 0.066），最后一层 0.722（对照 0.145），final norm 后余弦 0.60（对照 0.99）。

**结论：** 这个位置对数值噪声特别敏感，每个子层只有 bf16 噪声，逐层放大后翻转了结果。不是代码错误。

## 7. 合成模拟（2026-11-09 至 11-10，不是实测）

**这一节的数字都来自合成世界，不是实测。** 脚本和原始结果在 `test_sglang_liujg/clear_tree/sim/`（结果文件在 `sim/results/`），世界的设定见那里的 README。要点：
- 文本固定（greedy 语义），所有策略在同一批请求上配对比较。
- 参数按实测校准：b=1 时 OPT(8) 每轮约 3.5 个 token（实测约 3.6）；RTT 4 ms 时投机和 Target-only 在 b≈7–8 打平（实测短前缀 b≥7 时 Target-only 更快）。
- "最优静态"是在 (N ∈ {4, 8, 16}) × (τ 7 档) 的网格里事后挑的，偏强。
- 吞吐单位 tok/s；括号里的百分比相对最优静态。

**第 7 轮（7.8 节）推翻了 7.1–7.6 的收益结论，读之前先看 7.8：**
- 7.1–7.7 里的 OPT 用的停止规则和真实 OPT 不同：模拟器在"前沿最好路径分数 ≥ τ"时继续长；真实 OPT 在"前 N 路径概率之和 E 这一层的增量 > τ"时继续长（`opt_tree_ops.py` 的 `depth_rule`）。旧规则做出的静态基线平均弱约 4%，b=8 时弱 6–8%。旧网格也没有 N=2。
- 换成真实规则、网格加上 N=2 以后，在原来的世界里，ClearTree 核心相对最好的静态配置只高约 0.6%。原来的 +3.9% 主要来自偏弱的基线。

- 所以 E1、E2 用真实数据判断时，要看后悔或吞吐影响，不能只看偏差比例。
- 这项审计在真实系统里不需要额外的 Target 验证：补算前向给出被停下请求的真实下一层（dG），被接受路径到达叶子时，bonus token 就是叶子处的 y*（dA）。

- 给 ClearTree 已知的真实接受参数（oracle）也只有 6.5–7.2。
- 把宽度换成 W=2 也只有 6.4。

- **静态参数不能跨数据集通用。** b≥4 时，不同接受率的负载最优 τ 和 K 差别很大；用错极端负载的参数会损失 20% 以上。相近负载之间（中和高）损失 0–9%。
- **负载可以分开时：** 按数据集各调一套就够；同一种负载内，一套参数跨 b 最多损失约 4%。
- **负载混在同一个 batch 里时：** 单一折中配置 (4, 16, 0.4) 加开关已经接近静态能做到的最好，按类型分别设 τ 没有用。ClearTree 只在 b=4 多约 2%，在 b=1 和 b=8 没有优势。
- **ClearTree 目前做不到"不调参、自动适应各种负载"。** 它在高接受率负载下会少长层，这是规划本身的问题，要先修。
- **实测检验：** 在 2–3 个数据集上用现有 OPT 扫 τ，看最优 τ 是否不同，以及互换参数损失多少（plan.md 第 13 节的数据集）。

### 7.10 定位 ClearTree 少长层的原因，以及两条更简单的规则（第 9 轮，2026-11-10）

- **主因是接受率被低估：** 已知参数时差距基本消失。停止边界审计显示，高接受率下被停下的请求，实际收益比预测高 10–24%；下一层的快照预测是准的（比值 1.01）。
- **模拟器自身的原因：** 模拟器的在线学习把全局截距 a 从 0 开始、每个标签只走 0.01 步（`feasibility.py`）。高接受率下标签几乎全是命中、预测概率接近 1，梯度很小，a 收敛很慢。
- **改成最大似然拟合后，** 整体校准变得无偏（实际 / 预测 0.97–0.98），差距在 b=4 收回一半，b=8 只收回一点。但高接受率下几乎没有失败标签，截距和斜率直接撞到上下限（完全分离），需要先验或正则化。
- **K 固定 32 能收回 1–3 个百分点；成本裕量 1.0 没有一致的效果。**
- **已知参数时 b=8 仍差 4.9%：** 那里最优静态配置用 W=2，ClearTree 用 W=4。具体原因没有再查。
- **对设计的含义：** logistic 校准在接受率接近 1 时会饱和，几乎没有失败样本。高接受率是它的弱点，而停止边界审计里"实际 / 预测"的比值能在线发现这个偏差。

**R：两条更简单的规则。**

- **按 batch 算账（`BatchAccount`）：**
  - 每个请求下一层的收益 = c_i × ΔE_i。ΔE_i 是刚加的一层让它的前 K 路径概率和增加了多少，和真实 OPT 判断用的是同一个信号；c_i 是在线校准（实际接受数 / 预测的前 K 质量），按请求算，向全体均值收缩。
  - 每层保留收益最高的 m 个请求，m 只能是当前活跃数或更小的图档（8、4、2、1）；"它们的收益之和 − Θ* × 这一层的成本"大于 0 才继续。Θ* 和每档的层成本都在线学。
  - 不按负载调任何参数。
- **接受率 → τ（`OPTRhoTau`）：**
  - 在线估计按深度的接受率 ρ = Σa / (Σa + 停在树内的轮数)。这个量几乎不随 τ 变：低、中、高三种负载分别约 0.65、0.85、0.97。
  - 用 ρ 判断负载类别，再查一张从 7.9 节网格离线拟合的 τ 表。(W, K) 取 (4, 32)，它各负载的最优 τ 平均能拿到各负载最优的 97.9%。

  - 纯负载：各负载调好的最优静态配置（样本内）。
  - 混合负载：混合负载的最好静态配置（7.9 节，事后挑）。
  - 分阶段负载（先低、再高、再中）：同一批请求上跑过的静态候选里最好的一个。
- **按 batch 算账的短板在 b=1：** 那里最优宽度是 8，规则用的是 4。改用 W=8、K=32 以后（`d9b.json`），b=1 时低、中、高分别 −1.9%、−0.5%、−0.4%，混合负载 +0.4%。
- **按 b 选宽度后的整体结果：** b=1 用 W=8、K=32，b≥4 用 W=4、K=32。纯负载 9 格平均约 −0.2%，最差 −4.8%（高接受率，b=8）。b≥4 改用 K=16（在拟合范围内）时，平均约 −0.4%，最差 −7.1%。
- **混合和分阶段负载：** 按 batch 算账比事后挑的最好静态配置高 3–7.5%，和 ClearTree 相当（ClearTree K=16 高 0.2–2 个百分点）。
- **b=8 的混合负载：** Target-only（219.8）比所有静态配置都快。ClearTree K=16（220.2）和它持平，按 batch 算账（216.0）低 1.7%。
- **接受率 → τ 基本没用：** 纯负载平均 −2.5%，混合和分阶段负载 −1.2% 到 +1.1%。按类别整批切换 τ，跟不上请求之间的差异。

**结论（合成，待实测确认）：**
- 按 batch 算账的简单规则，加上按 b 选的 W，在不按数据集调参的情况下，基本追平了"每个数据集各调一套"的静态配置（平均约 −0.2%）。在混合负载和随时间变化的负载下，它比任何单一静态配置高 3–7.5%。
- 它不需要两段式 GLMM、快照库、子集 DP、K_g/K_v 和 C++ 规划器。和 ClearTree 核心相比只差 0–2 个百分点，而且在高接受率下比 ClearTree 稳。
- ClearTree 自身的问题出在接受率校准：高接受率下 logistic 模型会饱和，在线 SGD 收敛慢，最大似然会完全分离。如果保留 ClearTree，校准要换成能处理接近 1 的接受率的形式，或者用停止边界审计的"实际 / 预测"比值在线修正。

### 7.14 W 和 K 能不能在线选（第 13 轮，2026-11-10）

脚本：`ext11.py`（`BatchAccount4`：在线选 K、在线选 W）、`run13.py`、`analyze13.py`。结果：`r13.*.jsonl`、`analyze13.txt`。

**设定：** 规则都是修订后的第十版（首位 top-1 分类、按轮冻结、Θ_b、b=1 的保守开关）；种子 8–10；b = 1、4、8。

**负载：**
- 已知三种：低、中、高。
- 没见过的四种：
  - 中低（a=2.0）、中高（a=3.5）；

**方案：**
- **查表：** 第十版三.1 的表。
- **在线选 K：** K ∈ {8, 16, 32}，验证前比较"多验证那几个节点的 c_i × 路径分数之和"和"Θ_b × 验证耗时差"。验证耗时当作已经测好（相当于 V2 的结果），不在线学。

  - 估计各 W 下的每轮吞吐，可验证的深度上限取 ⌈K/W⌉+1；
  - 选吞吐最大的 W，切换要高出 2%。

- **对照：** 同一规则下，6 种固定 (W, K) ∈ {2, 4, 8} × {16, 32} 里，事后挑出的最好一种。

### 7.15 用已提交文本配对回放选 (W, K)（第 14 轮，2026-11-10）

脚本：`ext12.py`（`BatchAccount5`：配对回放、截窄审计）、`run14.py`、`run14b.py`（回放改用实测的层耗时）、`analyze14.py`。结果：`r14.*.jsonl`、`r14b.*.jsonl`、`analyze14.txt`。

**回放怎么做：**
- **依据：** greedy 解码时，提交的文本和树形无关。所以文本一旦已知（模拟里用 H，相当于之后几轮提交的 token），每棵已经建好的树都能按别的选项重新算一遍。
- **对每个候选 (W′, K′)：**
  - 宽度：把树逐层截成全局 top-W′（W′ ≤ 本轮的 W）；
  - 验证集：取前 K′ 个节点；
  - 接受数：真实路径沿这个验证集能走多深，再加 1 个 bonus；
  - 耗时：在实际耗时上加减差值，包括首层和各层的层成本差、验证耗时差（验证耗时按已测好处理）。
- **比较方式：** 每个候选都和当前选项在同一批轮次上配对比较。比当前更宽的候选，只能用 5% 的探索轮（真的用宽一档建树）来比较。
- **切换规则：** 按并发档分别维护，每 20 轮判断一次，高出 3% 才切换。回放第一次切换之前，跟着表走。

**场景：**
- 没见过的四种负载；
- 验证 ×10、Draft 快一倍、Draft 慢一倍，各用中、高两种负载；
- b = 1、4、8，种子 8–10。

**对照：** 同一规则下，6 种固定 (W, K) 里事后挑出的最好一种。

| 世界 | 查表 | 只在线选 K | 回放（层耗时在线学） | 回放（层耗时实测） |
|---|---:|---:|---:|---:|
| 没见过的负载（12 格） | −0.26%（−1.8%） | −0.10%（−0.9%） | −1.23%（−4.2%） | −0.20%（−1.2%） |
| 验证 ×10（6 格） | −2.89%（−8.8%） | −0.62%（−2.7%） | −1.63%（−3.9%） | −0.81%（−1.6%） |
| Draft 快一倍（6 格） | −0.39%（−0.9%） | −0.10%（−0.4%） | −1.42%（−3.6%） | −0.60%（−1.2%） |
| Draft 慢一倍（6 格） | −0.51%（−1.5%） | −0.28%（−1.2%） | −0.90%（−3.1%） | −0.21%（−0.7%） |
| 全部 30 格 | −0.86% | **−0.24%** | −1.28% | −0.41% |

（相对事后最好的固定 (W, K)；括号里是最差格。）

**截窄近似的审计（真按窄一档的 W 建树，和截窄的结果比较；深度、K 相同）：**
- 5–7% 的"请求 × 轮"上接受数不同；
- 平均差 −0.006 到 +0.022 个 token，相对接受数在 −0.16% 到 +0.54% 之间。
- 所以"宽树截窄当作窄树"的误差很小，可以用。

**回放在线学层耗时时为什么会输：**
- b=1 时，层成本模型只见过当前宽度的层，别的宽度只能按"图档 × W"等比例外推。可按拟合，每层约 5 ms 是固定开销，所以窄层的耗时被低估了约 30%。
- 回放因此高估了窄选项。追踪里，b=1、中高接受率时它估计 (2, 16) 比 (8, 32) 好 12.1%，实际是差的。
- 切过去以后，更宽的选项只能靠探索轮来比较，攒样本很慢，于是卡住了。
- 改用实测的层耗时后，b=1 的损失都收到 0.4% 以内。

**结论（合成）：**
- **接受数用回放算是准的，耗时必须来自实测：** 部署时用微基准测好每个 (图档, W) 的 Draft 层耗时，和 V2 测验证耗时一起做。
- **在这些世界里，只在线选 K 是最好的方法**（30 格平均 −0.24%）。回放加实测层耗时略差一点（−0.41%），差距主要来自约 3–4% 的探索轮，以及多候选比较的噪声。
- **W 的余地很小：** 大多数场景里事后最好的 W 就是表里的 W。回放只在少数格上更好，例如验证 ×10、高接受率、b=4：−1.6% 对只在线选 K 的 −2.7%。
- **回放更适合做审计工具：** 检查表里的 W 是否还合适，同时为停止边界审计、退出审计提供数据；不适合直接当控制器。

  - 同树重选 K 只能看到很小一部分影响，审计要直接看 f 偏离 1 的程度。
- **没在用的 K 变便宜（第 5 条）：**
  - 第二版检测确实看不到，在 b ≤ 4 时可能损失 3–6%。
  - 低频探测的性价比低：收回约一成，不变时持续花 0.2–0.4%。
  - 应该用部署、重新捕获图之类的事件触发全档重测，而不是靠随机探测。

- **重新打分没有整体赢过回放控制器：** 收回比例相近（72% 对 76%），表合适时的代价也相近（−0.28 对 −0.22 个百分点）。差别在代价的形式：启动突发是每个事件一次性的，回放控制器的 5% 探索是持续的。这里每次运行只有 700–2500 个投机轮。下面的长运行复核证实：突发的代价会被摊薄，持续探索不会。
- **和第 14 轮不矛盾：** 第 14 轮里回放控制器不如只在线选 K，是因为那些世界里表的 W 基本是对的。这里专门构造了 W 定错的世界。W 表对不对，决定了在线调 W 值不值得。

**长运行复核（L、L2 部分，`r18L.*.jsonl`、`r18L2.*.jsonl`、`analyze18L.txt`）：** 请求数是上面的 10 倍（每次 7000–14000 个投机轮），种子 8，b = 4、8，中、高接受率，世界只取基准和行便宜（表偏窄）。和同一种子的短运行对照。

| 做法 | 基准：相对查表（短 → 长） | 行便宜：相对事后最好的固定 W（短 → 长） |
|---|---:|---:|
| 回放控制器 | −0.66% → −0.35% | −0.45% → −0.09% |
| 重新打分，只 1% 探索 | −0.38% → −0.07% | −2.25% → −2.30% |
| 重新打分，启动事件 + 宽一档 | −0.63% → −0.07% | −1.66% → −1.59% |
| 同上，探索记录单独保留最近 200 条（L2，只跑了长运行） | — → −0.07% | — → −0.71% |

（各世界 4 个场景的平均；行便宜世界里查表相对最好的固定 W 是 −2.30%。）

- **一次性探索的代价确实被摊薄：** 表合适时，"启动事件 + 宽一档"从 −0.63% 降到 −0.07%，宽于表的轮次占比从 4.6–10% 降到 1.4–1.8%（剩下的是 1% 的持续探索）。回放控制器的 5% 持续探索不摊薄：长运行里仍有 4–5% 的轮次在探索，代价 −0.35%；基准中接受率 b=4 那格它切到了 W=8，长运行里 −0.74%。
- **但原来的重新打分在长运行里发现不了表偏窄：** 行便宜世界里几乎没有收回（−1.59%）。原因有两个：
  - 每格只在开头探索 30 轮，置信下界过不了门槛（真实增益 2–4%）；
  - 普通记录只保留最近 500 轮，开头的探索记录很快被挤掉；之后 1% 的持续探索在窗口里最多只留下约 5 条，永远攒不够 20 条。中接受率 b=4 那格唯一的一次切换，发生在分类器偶尔跳到"高"时新建的那一格里，主格一直没切。
- **探索记录单独保留之后（L2）能发现，但慢：** 行便宜世界从 −1.59% 收回到 −0.71%，表合适时代价不变（−0.07%）。高接受率 b=8 在第 4119 轮、中接受率 b=4 在第 5415 轮才切换（前者共约 7600 轮，后者约 12800 轮），宽于表的轮次只占 47–59%。回放控制器几百轮内就切换，收回到 −0.09%。
- **两者的取舍：** 按这组数，只有当部署里有超过约三成的表偏窄时，回放控制器的持续代价才划算（0.35(1 − p) + 0.09p = 0.07(1 − p) + 0.71p，p ≈ 0.31）。真实服务运行得更久，重新打分发现偏窄的延迟占比会更小。更大的启动探索（例如 100 轮）能加快发现，这一点没有测。

**结论（合成）：**
- W 表可能定错时（没有按部署的实测成本重做，或者运行中 Draft 的行成本变了），在线更新 W 能收回约七成损失；表合适时代价约 0.2–0.4 个百分点（重新打分不开突发探索时约 0）。
- 最直接的办法是让表跟着成本走：部署时和成本事件之后重做 W 表。理想切换说明这样几乎没有损失。在线更新只在表来不及重做时兜底。
- 如果做在线兜底，较好的形式是"按实测成本重新打分 + 事件触发的宽一档短探索 + 置信下界门槛"，不做真实配对确认；平时的探索很少，而且探索记录要单独保留，不能被普通记录的窗口挤掉。长运行里它在表合适时只多付 0.07%（回放控制器 0.35%），代价是发现表偏窄要慢得多（见上面的长运行复核）。

**B. 四种校准方法，同一预算**

- **设定：** 第 18 轮主对比的同一组场景（基准、行贵、行便宜、运行中变化；中、高；b = 1、4、8；种子 8–10；请求数 3 倍）。每格第一次出现（预热之后）和成本表变化时各开一个校准窗口，最多 200 轮，窗口外不探索。比较量 Y = 提交 token − Θ·耗时，Θ 在开窗时冻结；最小值得调整的增益 ε 为每轮提交 token 的 1%。
- **方法：**
  - **固定 30 轮：** 按 W=8 建 30 轮，配对回放，单侧下界（1.645 倍标准误）超过 ε 才切换。
  - **IPW 加分组序贯：** 每轮在 {2, 4, 8} 里等概率随机选一个真跑，各臂不配对；第 50、100、150、200 轮查看，z = 2.63；没有结论就保持。
  - **配对加置信序列：** 按还在比较的最宽候选建树，更窄的候选在同一棵树上回放；每轮更新正态混合置信序列（方差用样本估计，α = 5% 按候选数分），至少 10 对之后才判断；下界 > ε 就切，上界 < ε 就放弃这个候选，到预算还没结论就保持。
  - **多臂竞赛（Sequential Halving）：** 3 个 W 各真跑 33 轮，淘汰均值最差的，剩下 2 个再各跑 50 轮，最好的比当前高 ε 以上才切。

（相对每个场景事后最好的固定 W。）

- **测量方式的结论成立：** 不配对的两种（IPW、多臂竞赛）最差。IPW 在基准和行便宜世界里 42 个窗口有 40 个以"不确定"结束，只收回 30%；多臂竞赛真跑很差的臂，校准占 21–40% 的轮次。
- **配对加置信序列在表定错时和回放控制器相当：** 行贵 −0.65% 对 −0.65%，运行中变化 −0.45% 对 −0.60%，收回 73% 对 76%。行贵、高接受率 b=1 那格只用 3% 的轮次就从 −6.3% 收到 −0.5%。
- **但它在表合适时代价偏大，主要来自 b=1 的错误切换：**
  - 窗口在预热结束（第 10 轮）后立刻打开，Θ_b 和 c_i 还没稳定；只有 10 对样本就开始判断，用样本估计的方差偏小。
  - 基准世界 b=1 的 6 次运行里有 3 次切错：中接受率 2 次在第 19 轮（开窗后第 10 对样本）把更好的 W=8 切成 4；高接受率 1 次把 8 切成 2（那里最好的是 4）。中接受率 b=1 因此 −2.1%，高接受率 b=1 −1.2%。

- **短运行对事件触发不利：** 每次运行只有 700–2500 个投机轮，校准窗口占 12–22%。第 18 轮的长运行复核显示一次性探索的代价会被摊薄；这里没有跑长运行。
- **表偏窄时配对加置信序列仍不如回放控制器**（−1.03% 对 −0.49%）：中接受率 b=4 选择损失 1.4%，部分窗口到预算仍不确定。

**结论（合成）：**
- 测量方式比探索算法更重要：同一轮配对回放的方差是逐轮随机分配的 1/14 到 1/32。比较 W 时应以配对回放为主，真跑只用来提供更宽候选的样本；不要用逐轮 IPW 随机分配或多臂竞赛。
- 事件触发的配对校准：推迟开窗和提高最少样本数之后，表合适时几乎不花代价（长运行 −0.01%），但发现表偏窄变慢，到预算还不确定的候选以后不会再看。严格的经验 Bernstein 区间在这个样本量下太保守。
- 还要补的：最少样本数只用于切换，放弃可以提前；对"不确定"的候选，过一段时间（例如间隔逐次加倍）再开窗，并把各次窗口的配对证据累积起来；更宽候选只往宽一档探索。

### 7.21 起点用平表、成本从零在线学（第 20 轮，2026-11-11）

脚本：`ext17.py`（`BatchAccount10`）、`run20.py`、`analyze20.py`。结果：`r20.*.jsonl`、`analyze20.txt`。**本轮起在 conda 的 sglang 环境里运行**（Python 3.11.18、numpy 2.4.6），结果和以前 python3.10 的运行不逐位相同，所以参照组（事后最好的固定 W、平表）都在同一环境里重跑。

**设定：**
- **平表：** b=1 用 8，b=2–4 用 4，b≥5 用 4，与接受率无关。
- **世界：** 基准、行便宜、运行中变化（第 18 轮）；中、高接受率；b = 1、4、8；种子 8；请求数 3 倍。

- **在线学成本：**
  - 层耗时按 (图档, W) 记 EMA，没数据的格用线性模型补；
  - 验证耗时按 (b, K) 记"等待时间减首层估计"的 EMA；
  - 每个 b 档第一次出现时做计时探测：9 种 (W, K) 组合各 2 轮；
  - 某个层耗时持续偏离参照 15% 以上（连续 10 次）视为成本事件，重新探测并重开校准窗口。
- **已知成本：** 成本直接取世界的期望值，和第 18、19 轮相同。

| 世界 | 平表，已知成本 | 平表，在线成本 | 校准，已知成本 | 校准，在线成本 |
|---|---:|---:|---:|---:|

- **在线学成本只多付约 0.1–0.4 个百分点：** 同一场景配对比较，校准时在线比已知低 0.10–0.14 个百分点（单格 −0.8 到 +0.6）；不校准时低 0.15–0.38。主要来自计时探测，占投机轮次的 1–5%（投机轮很少的格最多 13%）。
- **层耗时学得准：** 估计误差 0.5–1.7%。成本事件在运行中变化世界的 6 次运行里都触发了 1 次，其他世界没有误触发。
- **验证耗时在不同 K 之间的差学不准：** K=32 和 K=8 的差，估计误差 20% 到 490%。因为按 T0 拟合，这个差只有 0.6–5 ms，比每轮的计时噪声还小。这里验证 token 几乎免费，选错 K 的影响很小；验证耗时随 K 明显变化时，需要更多样本或配对的测法，这一点没测。
- **从平表起步，校准的收益集中在表错得多的格：**
  - 运行中变化世界平均 +2.7%，最多 +8.7%（高接受率 b=8：平表 −11.5% → −3.0%）；
  - 行便宜、中接受率 b=4：−4.0% → −0.7%。
  - 基准世界里，短运行中校准反而多付约 0.2 个百分点。
- **新发现：回放低估了更窄的宽度。**（第 24 轮诊断更正：这一格回放没有低估 W=2，窗口不确定主要是统计功效不够；回放偏差在 ±1 个百分点内、方向随负载变。见 7.25 节）
  - 基准、高接受率 b=8：平表用 W=4，最好的是 W=2（约高 3%），但两种成本模式的窗口都以"不确定"结束，一直停在 W=4，亏 2.0–2.9%。
  - 推测原因：回放把 W=4 的树截成 W=2 时，深度和退出都沿用 W=4 的生长日程；而 W=2 在高接受率下的好处正是每层更便宜、能长得更深，回放看不到。
  - 第 18、19 轮里这一格的表本来就是 W=2，所以没暴露。
  - 这是回放的系统性偏差，需要少量真跑较窄 W 的核验轮来估计，或者回放时让窄树按自己的规则重新决定停止（但它只能停得更早，不能长得更深）。

**结论（合成）：**
- 不做离线测量、改为在线计时探测加 EMA，代价约 0.1–0.4 个百分点，层耗时能学准；验证耗时在 K 之间的小差学不准，但在这种成本下影响不大。
- 从平表起步时，校准能把表错得多的格收回大部分，但回放对"更窄、更深"的选项有系统性低估，单靠回放发现不了这类改进。

### 7.22 成本模型加前缀长度项，在线学（第 21 轮，2026-11-11）

脚本：`ext18.py`（`World21`、`BatchAccount11`）、`run21.py`、`analyze21.py`。结果：`r21.*.jsonl`、`analyze21.txt`。conda sglang 环境。

**世界：** 每个请求有自己的提示长度 p0，前缀 ℓ = p0 + 已生成的 token。真实成本：
- 层耗时 = 原来的 (图档, W) 成本 + κ_W·Σℓ（活跃请求的前缀和），κ_W = k_d·(0.5 + 0.125·W)；
- 验证耗时 = 原来的 (b, K) 成本 + κ_t(K)·Σℓ（全部请求），κ_t(K) = k_t·(0.5 + (K+1)/34)；首层也带自己的前缀项。
- 前缀组合：全短（100–400）、长短混合（一半 3000–5000）、全长；
- 强度："强" k_d = 0.001、k_t = 0.002（4 个约 4000 的前缀时层耗时多约 16 ms、验证多约 32 ms），"中"是其 1/4；
- 场景：（全短, 强）、（混合, 强）、（全长, 强）、（混合, 中）；中接受率；b = 1、4、8；种子 8。
- 不做 W 校准（W 用第十版的表），K 在线选，不用投机开关（这个世界里 Target-only 没有前缀项，开关会有偏）。

**策略：**
- **已知：** 真实成本，按净收益 ĝ_i − Θ·κ_W·ℓ_i 决定保留哪些请求；
- **不管前缀：** 第 20 轮的在线 EMA，按 (图档, W) 和 (b, K) 记；
- **前缀感知：** 带遗忘（0.999）的在线回归：每个 W 一个 [1, 图档, Σℓ]；验证耗时跨 K 合并一个 [K 档截距, b, Σℓ, (K+1)·Σℓ]；按净收益排序；
  - 最初每个 K 单独回归，很少用的 K 定不出前缀斜率（冒烟测试里 K 差的误差超过 280%），所以改成合并；
- **前缀感知、只按 ĝ 排序：** 估计同上，用来分开"成本估得准"和"按净收益排序"的作用。
- 在线的三种都做第 20 轮的计时探测和漂移检测；前缀感知的漂移检测看"实测 / 预测 − 1"的残差。

| 场景 | 不管前缀 | 前缀感知 | 前缀感知、只按 ĝ 排序 |
|---|---:|---:|---:|
| 全短，强 | −0.23% | +0.01% | −0.01% |
| 长短混合，强 | −2.40%（最差 −3.5%） | −0.17% | −0.22% |
| 全长，强 | −0.21% | 0.00% | −0.08% |
| 长短混合，中 | −1.23% | −0.47%（最差 −1.4%） | −0.35% |
| 12 个场景平均 | −1.02% | −0.16% | −0.17% |

（相对"已知真实成本"，各场景平均。）

- **前缀项能在线学准：** 前缀感知的层耗时预测误差 0.2–0.3%，12 次运行没有一次误触发成本事件。
- **不管前缀的模型在长短混合时出问题：** 前缀随生成增长、batch 里长短请求进进出出，层耗时预测误差 2–8.5%，漂移检测被当成成本变化误触发 8–32 次，计时探测跑了 180–617 轮。全短或全长时前缀变化相对小，它基本没问题（约 −0.2%）。
- **收益主要来自成本估得准，不是按净收益排序：** 两种排序平均只差 0.01 个百分点。这个世界里退出按图档进行，排序只在跨图档时有影响。
- **K 之间的验证耗时差仍然学得不稳：** 合并回归后多数格误差 3–34%，但 b=1 时 43–182%（b=1 时几乎总选 K=32，K=8 的截距只来自探测轮）。在这些世界里，对吞吐的影响不大。

**结论（合成）：**
- "图档 / W 的基础项 + κ·Σℓ"的加和模型在线可学，代价只有探测轮；前缀长短混合时必须有前缀项，否则成本估计偏差大，漂移检测还会被前缀增长误触发。
- 验证耗时要跨 K 合并回归，否则很少用的 K 学不到前缀斜率；很少用的 K 的截距仍要靠探测，可能形成"估不准 → 不选 → 更估不准"的循环。

### 7.23 整 batch 统一分配验证预算（第 22 轮，2026-11-11）

脚本：`ext19.py`（`World22`、`BatchAccount12`）、`run22.py`、`analyze22.py`。结果：`r22.*.jsonl`、`analyze22.txt`。conda sglang 环境。

**问题：** 现在每轮所有请求共用一个 K。如果 Target 支持每个请求不同的验证长度（变长验证，像 ForeSpark 那样把各请求的 token 拼成扁平 batch，按总 token 数分档捕获图），把验证预算在整个 batch 里统一分配能多多少。

**世界：** 第 21 轮的前缀世界（强档前缀项），加两处：
- 验证 token 成本可乘 10；
- 变长验证的耗时 = c0 + c_b·b + v_tok·档(Σ(K_i+1)) + Σ_i k_t·(0.5·ℓ_i + (K_i+1)·ℓ_i/34) + 首层；总 token 数向上取到捕获档（8、16、24、32、48、64、80、96、128、160、192、256……）。各请求 K_i 都相同且不取整时，就是统一 K 的耗时。
- 场景：前缀全短或长短混合 × 验证 token 成本 ×1 / ×10 × 负载 mid 或 het（het 让各请求的接受率从很低到很高）× b = 4、8；种子 8；成本已知；W 用第十版的表；不做 W 校准，不用投机开关。

**做法：**
- **统一 K（第十版）：** 每轮在 {8, 16, 32} 里选一个 K，生长和验证同一口径；
- **统一分配，只改验证：** 生长不变。验证前把所有请求的节点放在一起，净边际价值 = c_i·路径分数 − Θ·k_t·ℓ_i/34，取正的、从大到小，直到总 token 数到一个档；在各档里取 J 最大的那档。同一请求内净价值随排名下降，所以每个请求取到的是自己的前 K_i 名，祖先闭合。
- **统一分配，生长也改：** 每层"停下的价值"用统一分配下的 J；请求 i 下一层的增益按不小于它当前 K_i 的最小捕获 K 计。

| 分组 | 只改验证 | 生长也改 |
|---|---:|---:|
| 全部 16 个场景 | **+1.58%**（+0.7 到 +2.8） | +0.11%（−1.2 到 +1.6） |
| 全短前缀 | +1.34% | −0.04% |
| 长短混合 | +1.83% | +0.26% |
| 验证 ×1 | +1.57% | +0.85% |
| 验证 ×10 | +1.60% | −0.62% |
| 接受率中等（mid） | +1.45% | +0.03% |
| 接受率差异大（het） | +1.72% | +0.19% |

（相对统一 K。）

- **只改验证的统一分配，16 个场景全部为正**（+0.7% 到 +2.8%）。长短混合、接受率差异大时收益最大（例如混合、het、b=8：+2.8%）：前缀长的请求每多验证一行更贵，接受率低的请求多验证收益小，统一分配把验证名额挪给了更值的请求。
- **收益里也包含粒度更细的效果：** 统一 K 只能取 8、16、32，统一分配下每个请求可以取任意 K_i。这两部分没有分开量。
- **生长也改的版本没有收益**（平均 +0.11%，验证 ×10 时 −0.62%）。下一层增益的近似（按当前 K_i 往上取捕获档）不够好，在验证贵时会多长层。
- **统一分配要付的代价已经计入总 token 取档的浪费，但没计实现开销：** 变长验证的元数据准备、按总 token 档捕获图的数量、eager 路径的额外开销都没有模拟。

**结论（合成）：** 在 Target 支持变长验证的前提下，只在验证前做整 batch 统一分配，平均多约 1.6%，各场景都为正；生长规则不用跟着改。值不值得做，取决于真实实现的开销（共享代码改动：`EagleVerifyInput` 每个请求一个长度、`qo_indptr` 改成累加、接受 kernel 的位置映射、按总 token 档捕获图，NPU 还要核实 `tree_paged_fia` 是否支持不同的 query 长度）。

### 7.24 由成本模型推 W 的阈值，对比其他在线调 W 的做法（第 23 轮，2026-11-11）

脚本：`ext20.py`（`BatchAccount13`）、`run23.py`、`analyze23.py`。结果：`r23.*.jsonl`、`analyze23.txt`。conda sglang 环境。

**设定：** 前缀世界（强档前缀项），成本已知且含前缀项，都从平表起步（b=1 用 8，其余用 4），种子 8，请求数 3 倍。各做法共用同一套回放：截窄后的树可以按自己的预测净价值停得更早；在"加深轮"上（规则停下后再多长 2 层）也可以停得更深。

**世界：**
- 基准：中接受率、全短前缀；
- het：各请求接受率差异大、前缀长短混合；
- 分阶段：het 加混合前缀，请求按接受率先低、再高、再中的顺序到达；
- 以上各跑 b=4 和 8；
- b 变化：het 加混合前缀，并发 2（0–40 秒）→ 8（40–80 秒）→ 4（80–120 秒）。

**做法：**
- **平表、固定 W=2/4/8：** 固定 W 取每个场景最好的那个作参照；
- **由成本模型推阈值（derived）：**
  - 每一档的价值 ΔA(h)：同一轮里每个请求在宽一档和窄一档下提交 token 的差，按该请求自己的首位命中率 h 分箱，跨 b 共用，用保序回归约束成随 h 不增；
  - 层数 L：两档在同一批轮次上的回放层数；
  - 成本差：Θ_b × 两档的模型耗时差，按每层都满员、整个 batch 的 Σℓ 计；
  - 价值的置信界超过成本差加 1% 余量才切换，同一提议要连续 10 轮，切换后停留 150 轮；
  - 每个 b 档出现 50 轮后开 80 轮窗口按宽一档建树，其中 1/4 是加深轮；"不确定"时按 1000、2000…… 轮的间隔再开窗。
- **derived2：** 成本差改用同一批轮次上两档模型耗时差的 EMA；如果下一档的价值（按收益递减，是上界）已经抵不上加宽的成本，就不去探索更宽的一档；窗口 60 轮。
- **按格校准（cellcal）：** 第 19 轮修正版（事件触发、配对加正态混合置信序列、30 对）。
- **回放控制器（replay14）：** 每轮回放更窄的，5% 的轮次往宽一档探索，每 20 轮判断一次。
- derived 的"停留 150 轮、连续 10 次"和 derived2 的两处修改，都是看过冒烟测试后加的。

| 世界 | 平表 | derived | derived2 | 按格校准 | 回放控制器 |
|---|---:|---:|---:|---:|---:|
| 基准 | +0.01% | −1.07% | −0.76% | **+0.15%** | −0.41% |
| het | −1.21% | −1.17% | −2.30% | −0.49% | **−0.34%** |
| 分阶段 | −1.92% | **−0.15%** | −3.11% | −1.20% | −0.34% |
| b 变化 | −1.25% | −1.05% | −3.72% | −1.62% | **−0.73%** |
| 7 个场景平均（最差） | −1.07%（−2.8） | −0.83%（−2.0） | −2.29%（−4.2） | −0.67%（−1.6） | **−0.42%（−0.9）** |

（相对每个场景事后最好的固定 W。）

- **由成本模型推阈值没有更好。** derived 平均 −0.83%，只比平表好 0.24 个百分点；它在基准 b=8 把 W=4 错切成 2（−1.96%），在分阶段世界最好（−0.15%）。derived2 成本差估得更准，反而一次都没切（平均 −2.29%，比平表还差），还白付了探索的代价。
- **原因在价值那一侧：**（第 24 轮诊断更正了下面"低估更窄"的说法：基准 b=8 从 W=4 的树回放 W=2，回放反而高估 W=2 约 0.7 个百分点，和 derived 在这里错切成 2 一致；偏差方向随负载变，见 7.25 节）回放低估"更窄、更深"的选项（加深轮只占窗口的 1/4），ΔA 偏大，规则倾向于保持较宽的 W。derived 的成本近似偏高，恰好部分抵消了这个偏差，所以有时能切对；成本算准之后，偏差就暴露出来了。相邻两档的价值和成本常常只差 1–2%，任何一侧的小偏差都会让判断翻转。
- **回放控制器在这组世界里最好**（平均 −0.42%，最差 −0.9%）：分阶段和 b 变化的世界里没有成本事件，事件触发的方法不会重新校准，持续探索的方法能跟上。
- **按格校准在静态世界里好**（基准 +0.15%，het −0.49%），在分阶段和 b 变化的世界里跟不上（−1.2%、−1.6%）：开窗时如果正处在低接受率阶段，校准结果之后就不再更新。
- **平表在这组世界里只差约 1%：** 平表的 W=4 本来就接近最优（最好的固定 W 多是 2，只高 1–3%）。

**结论（合成）：**
- 成本模型让成本那一侧可以现算，但在线调 W 的难点在价值那一侧：回放对"更窄、更深"有系统偏差，相邻两档差距又小。不先解决价值偏差（例如少量真跑较窄 W 的核验轮），由成本模型推阈值不会比按格校准或回放控制器好。
- 负载会随时间变化、又没有事件可以触发时，持续低比例的探索（回放控制器）比事件触发的校准更稳。

### 7.25 回放是否低估更窄的宽度：同一轮真长一棵窄树的诊断（第 24 轮，2026-11-12）

**设定：** 主策略固定一个建树宽度（4 或 8）。每个非热身轮，在主轮之前用同一批请求状态、同一个价格 Θ、同一组 c_i、同一条生长规则，在独立的随机流上另外长几棵树，主运行不受影响（主运行吞吐和不带诊断的固定 W 运行逐位相同）。比较每轮的 Y = 提交 token − Θ·模型时间，也就是校准时比较的量，下面都写成占建树宽度每轮 token 的百分比。
- **回放估计：** 从建出来的树截窄，按策略自己的回放规则算。
- **真值：** 真按窄宽度、按自己的规则长一棵树。
- **偏差拆成三部分：**
  - 截窄近似：真窄树沿用宽树每层的请求日程，减去截窄的结果；
  - 退出/停止：窄树按自己的规则退出，减去沿用日程；
  - 深度截断：不限层数，减去最多和宽树一样深。

两种设定：
- ext20：第 23 轮的世界和回放，可以提前停，有加深轮；
- ext15：第 18–20 轮的世界和回放，深度和退出都沿用宽树。

两种设定都跑高、中接受率；ext20 另加 het（混合前缀）。b = 4、8，种子 8。

**比较 W=2 和 W=4（都在 W=8 的树上回放，即按最宽候选建树的窗口比较的东西）：**

| ext20 | 高 | 4 | +1.64% | +1.20% | +0.44 | +0.7% |
| ext20 | 中 | 8 | −1.24% | −1.25% | +0.01 | −1.8% |
| ext20 | 中 | 4 | −3.50% | −3.31% | −0.19 | −4.1% |

- **截窄近似可以忽略：** 所有格里 |真窄树沿用日程 − 截窄| ≤ 0.17 个百分点。
- **偏差来自退出/停止和深度截断，方向随负载变：**
  - 高接受率：相对 W=8 回放低估更窄的宽度 0.2–1.2 个百分点；相对 W=4 偏差在 ±0.35 个百分点内；窄树按自己的规则在 3–23% 的轮次里长得更深，这是收益。
  - 中接受率和 het：多数格回放反而高估更窄的宽度，高估 0.5–1.0 个百分点。窄树按自己的规则长得更深（10–48% 的轮次），但长过头了，自己的规则反而更差。

- **加深轮（多长 2 个 W 宽的层）没有系统改善：** 中接受率下反而把 2 比 4 的估计推得更负（ext20 中 b=8：−1.72%，真值 −1.25%）。

**第 20 轮那一格（ext15 高 b=8，7.21 节）：**
- 回放没有低估 W=2：从 W=8 的树回放，估计 +1.73%，真值 +1.36%；从 W=4 的树回放，估计 +2.83%，真值 +2.88%。
- 窗口以"不确定"结束，主要是统计功效不够：
  - 每轮配对差的标准差约 6–7%，效应只比 ε=1% 高 0.4–1.8 个百分点；
  - 按第 19b 轮的置信序列，要约 940 轮（从 W=8 的树）或约 180 轮（从 W=4 的树）才能判定；
  - 窗口预算是 200 轮，开头还要先按 W=8 建树。
- "真值"在两种建树宽度下不同（+1.36% 对 +2.88%），因为 Θ 来自正在运行的策略：W=8 运行时吞吐低、Θ 低，时间便宜，更宽的选项显得更好。窗口里 Θ 在开窗时冻结，这一项影响多大没有单独量。

**第 23 轮基准 b=8（ext20 中 b=8）：** 从 W=4 的树回放 W=2，估计 +0.08%，真值 −0.63%，回放高估了 W=2，和 derived 在这里把 W=4 错切成 2 一致。

**结论（合成）：**
- 7.21 节"回放系统性低估更窄宽度"的推测不成立：
  - 截窄近似可以忽略；
  - 偏差来自"退出和停止沿用宽树"与"深度截断"，在 ±1 个百分点内，方向随接受率变；
  - 第 20 轮那一格是功效问题，不是偏差。
- 这个偏差的大小和 ε=1%、相邻两档 1–2% 的差距同量级，足以让判断翻转（第 23 轮 derived 的错切）。
- 让探测轮的树包含每个候选自己会长出的树（并集探测轮），能去掉退出/停止和深度两部分；加深轮去不掉。
- 功效方面，按要比较的那一档建树（而不是按最宽的候选）、或者放宽窗口预算，比修偏差更直接。

### 7.26 快速收敛版和回放控制器对比（第 25 轮，2026-11-12）

**设定：** 都从平表起步（b=1 用 8，其余用 4），成本已知且含前缀项，按 b 档调 W。
- 世界：第 23 轮的 7 个（基准中接受率、het、接受率分阶段变化、b 随时间变化），加高接受率短前缀 b=4、8 两个。
- 运行：短运行（3 倍请求）种子 8、9，长运行（10 倍请求）种子 8，共 27 组。

两种做法：
- **回放控制器：** 第 14 轮的做法。每轮回放更窄的；5% 的轮次按宽一档建树；每 20 轮看一次，配对收益 > 3% 就切。
- **快速收敛版（`ext21.BatchAccount14`）：**
  - **并集探测轮：** Draft 为每个候选宽度按它自己的规则（自己的退出、深度、K）长树，这一轮付并集的层耗时，提交的仍是当前宽度那棵树的 token。每个候选的 Y 精确、两两配对。
  - **粗筛：** b 档出现 50 轮后做 16 轮全宽度的并集探测，此后每 2000 轮重做一次。差距的均值 + 2.5 se 低于 −3% 的宽度被排除；冒烟时用随时有效的半径，16 轮时约 10%，什么都排除不掉，改成了一次性检验。粗筛的数据同时用作相邻两档的配对样本。
  - **窄一档：** 每轮从当前树免费回放，减去探测轮上估出的回放偏差。
  - **宽一档：** 只用探测轮的精确配对差。
  - **探测比例：** 5%，候选为 {窄一档, 当前, 宽一档}，去掉已排除的。
  - **判定：** 每 10 轮看一次，置信序列下界 > ε = 每轮 token 的 0.25% 就切。窗口不关，用滑动窗口。

**结果（相对每个场景事后最好的固定 W）：**

| | 平表 | 回放控制器 | 快速收敛版 |
|---|---:|---:|---:|
| 全部 27 组平均（最差） | −1.41%（−6.0） | **−0.50%（−3.0）** | −1.28%（−3.4） |
| 短运行 | −1.45% | **−0.62%** | −1.49% |
| 长运行 | −1.33% | **−0.27%（−0.6）** | −0.85%（−2.5） |
| 基准（表本来合适） | +0.04% | −0.28% | −0.54% |
| het（接受率差别大、前缀混合） | −0.98% | **−0.53%** | −2.21% |
| 接受率分阶段 | −1.61% | −0.45% | −0.50%（长运行 +0.13%、+0.35%，最好） |
| b 随时间变化 | −0.44% | **−0.31%** | −2.07% |
| 高接受率 | −3.57% | **−0.86%** | −1.48% |

- **回放控制器整体最好。** 高接受率 b=8 第 49 轮就切到 W=2；它的 3% 门槛不需要置信序列，差距大时很快。
- **快速收敛版主要亏在并集探测轮的代价：**
  - 平均每轮多 0.4–3.1 ms 的 Draft 时间，约占吞吐的 0.5–1.5%；
  - b 随时间变化时每个 b 档都要粗筛，16 轮全宽度探测含 W=8，短运行亏 2.8–3.3%。
- **粗筛常排除不掉 W=8。** 在 het 和混合前缀下，W=8 差 8–14% 也排除不掉（前缀混合使每轮差的方差大），之后每个探测轮都要长 W=8 的层（het b=8 每轮多 2.5–3.1 ms）。
- **小 ε 的置信序列在差距小时太慢，偏差修正也不总能防住错切：**
  - het b=8（W=2 好 1.6–1.8%）：短运行种子 8 没切，种子 9 第 1419 轮才切，长运行第 4129 轮才切；回放控制器第 109 轮就切了。
  - 长运行 het b=4：W=4 最好（W=2 差 1.1%），快速收敛版第 449 轮切到 W=2（−2.22%）；回放控制器没有切。
- **快速收敛版只在长运行、接受率分阶段的世界里最好**（+0.13%、+0.35%，回放控制器 −0.38%、−0.45%）：低接受率阶段结束后，它切到 W=2 比回放控制器早 400–500 轮。

**结论（合成）：**
- 照现在这样组合的快速收敛版，没有比回放控制器好。
- 精确的并集探测轮去掉了回放偏差，但每轮要为每个候选各长一棵树，Draft 多花的时间比偏差本身（±1 个百分点）还贵。
- 小 ε 的置信序列在相邻两档只差 1–2% 时要几百到几千轮，差距大时又比 3% 门槛慢。
- 回放控制器的粗规则（3% 门槛、每 20 轮看一次）在这组世界里更划算：差距 ≥ 3% 时很快切，差距小时基本不动，代价只是 5% 宽一档探索。

### 7.27 回放控制器加在线成本模型（第 26 轮，2026-11-12）

**设定：** 检验第十一版的组合（`ext22.BatchAccount15`）：回放控制器（D62），成本用 D61 的在线回归（计时探测 + 残差漂移检测），回放耗时按第十一版的口径算：实测耗时 − 实际日程的模型耗时 + 候选日程的模型耗时。
- 世界：第 25 轮的 9 个静态世界，加 3 个运行中成本变化的世界（第 400 个投机轮时 Draft 层成本整体 ×3 或 ×0.3：中接受率 b=4 ×3、×0.3，高接受率 b=8 ×0.3）。

- 参照：静态世界的固定 W、平表、第 25 轮的回放控制器取自 r25（同一代码路径）；成本变化世界单独跑。
- 核对：成本已知、按第 23、25 轮的耗时口径（模型耗时 + 5 ms）时，新写的策略和 r25 的回放控制器逐位一致。

- **第十一版的组合成立：** 在线成本下，回放控制器比平表（在线成本）平均好约 1 个百分点（−0.80% 对 −1.81%），长运行 −0.42%。
- **在线成本的代价约 0.3 个百分点：** 平表上在线学成本多付 0.25 个百分点（主要是计时探测轮，每个 b 档 18 轮，成本事件后重来），回放控制器上多付 0.34 个百分点，即控制器本身因为成本有误差只多亏约 0.1 个百分点。层耗时的预测误差 0.1–0.6%；成本变化世界里漂移检测每次运行触发 1 次。
- **两种耗时口径几乎一样：** 成本已知时，第十一版的口径和"模型耗时 + 5 ms"的平均差 0.03 个百分点，只有两格切换时刻不同。

- **在线成本带来的问题：**
  - 长运行 het b=4：W=4 最好（W=2 差 1.1%），在线版第 67 轮就切到 W=2 并一直留在那里（−1.32%，成本已知时 −0.38% 不切）。刚探测完时，W=2 的成本只有几轮探测样本，第一次判定就翻过了 3% 门槛；切过去以后，回到 W=4 要宽一档探索的收益超过 3%，而真实差距只有约 1%，所以回不去。
  - 短运行种子 9、分阶段 b=4：在线版切换 5 次（成本已知时 1 次），其间漂移检测误触发 1 次，−1.07%（已知 −0.64%）。
  - 短运行种子 8、分阶段 b=8：−2.28%（已知 −0.45%）；短运行种子 9、高接受率 b=4：一直没切，−3.69%（已知 −2.97%，第 689 轮才切）。

- **成本变化世界没有真正考到"跟着成本换 W"：** 三个世界里成本变化前后最好的 W 都没变（中接受率 b=4 一直是 4，高接受率 b=8 一直是 2），控制器在变化后都没有切换。在线版的漂移检测都触发了，重新探测后继续运行，累计量不清零没有造成问题，但这不能说明成本变化后能及时换 W。

**结论（合成）：**
- 第十一版"回放控制器 + 在线成本模型"可以用：比平表（在线成本）平均好约 1 个百分点，在线学成本的总代价约 0.3 个百分点，其中控制器本身多亏约 0.1 个百分点。
- 主要风险在刚探测完、成本样本少时的第一次判定：可能被成本误差带着切到稍差的宽度，而 3% 的门槛又让它回不来。可以考虑的修正（没有模拟）：探测后再等一段（例如每个 W 的层耗时样本够 N 个）才允许第一次判定，或者第一次判定用更高的门槛。
- 第十一版回放耗时的口径（实测耗时 − 模型耗时 + 候选的模型耗时）和模拟里原来的口径结果几乎一样，可以保留。

### 7.31 成本事件按来源区分、切窄后复核、收紧下一层增益（第 30 轮，2026-11-12）

**设定：** `ext24.BatchAccount17`，`run30.py`。基线是现行第十一版：回放控制器、在线成本、D65、D67 的冷却（第 29 轮的"G1"；新代码关掉三项改动时和它逐位相同）。三项改动分别单独加在基线上，和基线配对比较：
- **src（成本事件按来源区分）：**
  - 验证残差超标时，先把三个 K 档在同一 b 档里各强制跑 2 轮（W 按控制器的当前值），算各 K 的残差均值（ms）。
  - 最大最小之差 ≤ max(4 ms, 0.3 × |平均残差|) 时，判为和 K 无关的整体偏移：把验证回归的三个 K 截距一起平移，不算成本事件，控制器累计量不动。
  - 否则是验证事件：只清验证回归、只探 K（每个 K 2 轮），清零控制器累计量。
  - 层残差超标时：只清层回归、只探 W（每个 W 2 轮），清零控制器累计量。
  - 检查不受冷却限制，事件受限。
- **recheck（切窄后复核）：** 切到更窄的 W′ 时，存下切换时的累计量和 W′ 层回归的系数快照。W′ 真跑 20 个普通轮后，f = 实测层耗时之和 ÷ 快照预测之和；按 (f − 1) × 候选累计的模型层耗时修正候选耗时，修正后收益 < 1% 就切回，并恢复修正后的累计量。
- **tight（收紧下一层增益）：** ĝ_i^K = c_i × Σ_{最新一层的节点 j} max(0, s_j − θ_K)，θ_K 是树里第 K 大的路径分数（不足 K 个节点时为 0），代替上一层的增量 c_i·ΔE^K。

为省时间，只跑改动可能起作用的组。跳过的组在构造上和基线相同，在 base b=4 种子 8 上抽查过逐位相同：
- **src：**
  - 第 29 轮的 RTT 世界 12 组；
  - 第 28 轮世界里基线有过漂移触发的 23 组（共 45 组）；
  - 新世界 vchg：第 400 个投机轮起每个验证 token 的成本 ×5，和 K 有关；中接受率 b=4、高接受率 b=8 各 3 组。
- **recheck：** 第 28 轮世界里基线切窄过的 29 组。
- **tight：**
  - 第 28 轮世界的短运行 30 组（没有长运行）；
  - 新世界 step：K ≥ 16 时验证耗时多 12 + 1.5·b ms，中接受率、短前缀，b = 1、4，各 3 组。
- vchg 和 step 只有配对差，没有固定 W 参照。

| src | RTT 世界 12 组 | **+0.43%**（−0.88 到 +1.13），11 组更好 |

**30b：K 检查的改法（`run30.py` 的 D、E 部分，`src_pre`、`chk_z`、`chk_n`）**
- **问题：** 上面的 src 在 RTT 世界里做了 74 次 K 检查，记录到的 62 次里只有 26 次判为共同偏移。看原始残差，错判来自噪声：单轮验证残差的标准差约 4 ms（b=8 约 4.4 ms，b=4 约 3.8 ms），每个 K 只跑 2 轮时，三个均值只因噪声就能差约 10 ms；例如高接受率 b=8 跳变时 K=16 的两轮残差是 7.1 和 16.7 ms，而容差只有约 4.6 ms。
- **用触发前的系数算残差（`src_pre`，只做了试跑）：** 在验证残差刚开始超标时存下系数，检查时用它算残差。高接受率 b=8 跳变仍判为不一致（平均 15.4 ms、相差 7.6 ms），判断不变，没有正式跑。
- **按平时残差的标准差放宽容差（`chk_z = 2.5`，只做了试跑）：** 容差到 15–18 ms，RTT 跳变判对，但验证 token 成本 ×5 也被判成共同偏移（相差 17.5 ms < 容差 18.2 ms），没有正式跑。
- **每个 K 跑 4 轮、容差用检查自身的合并标准差（`chk_n = 4`，"src4"）：** 容差 = max(4 ms, 0.3 × |均值|, 3.3 × s / √4)。在 src 起作用的 RTT、vchg 世界和第 28 轮世界里做过检查的 5 组上跑，共 23 组：

| | 相对 src | 相对现行设计（G1） |
|---|---:|---:|
| RTT 跳变（6 组） | −0.04% | +0.49% |
| RTT 来回切换（6 组） | +0.57% | +0.90% |
| vchg（6 组） | −0.07% | +0.04% |
| 第 28 轮世界里做过检查的 5 组 | −0.13% | +0.23% |

  - RTT 世界相对最好的固定 W：src4 −0.47%，src −0.73%，现行设计 −1.15%，不带验证检测 −0.88%；相对现行设计配对 +0.70%。
  - 分类：RTT 世界 49 次检查，记录到的 45 次里 44 次判为共同偏移，成本事件从 15 次降到 1 次；vchg 高接受率 b=8 三组仍判为不一致（相差 23.5 ms，容差 6.5 ms）。
  - 代价：每次检查 12 轮，比 src 多 6 轮。变化本来就判对、或者检查很少的世界里约 −0.1 个百分点。
  - het b=4 种子 8 在计时探测刚做完时误触发，src4 判成共同偏移、平移截距，相对现行设计 −0.72%（src 判为不一致，−0.44%）。

**X：拿掉按 K 遗忘。** `r32x.0/1.jsonl` 共 33 条。v12-perk 是 v12 去掉按 K 遗忘，仍有毛刺防护、K 检查超时、初次探测不占上限。现行设计的基线来自 `r32p`、`r32k`、`r32v`。百分比相对现行设计；「同组上的 v12」来自 `r32v`。

- RTT 来回切换上相反：v12 是 +0.34%，去掉之后是 −0.42%。撤回不是因为它在所有世界上都更好。
- RTT 一次跳变上另有 v12-rob（去掉毛刺防护、保留按 K 遗忘）6 组 −0.02%（−0.56 到 +0.52），同组 v12 是 −0.40%。分阶段 b=8「去掉毛刺防护回到约 +0.1%、只去掉按 K 遗忘仍是 −1.3% 和 −1.7%」不在这 33 条里。

**结论：**

- 确认的问题：冷却会挡住接连发生的真实成本变化。去掉冷却之后，第 31 轮那种连续变化平均 +7.10%，层成本来回变平均 +5.63%。v12（含按 K 遗忘）112 组平均 +0.98%；收益在连续变化（+6.32%）、层成本来回变（+3.81%）和毛刺（+1.54%）。
- 没有收益、不采用：事件令牌桶。连续变化上它和去掉冷却一样，层成本来回变时少了约 2 个百分点，压住过触发的 6 组里也只少掉约 0.2 个百分点。没在用的 K 做持续探测，成本不变时 +0.03%，K=32 变便宜时 +0.09%。按 K 遗忘撤回：K=32 变便宜从 −0.45% 回到 −0.12%，RTT 一次跳变从 −0.40% 回到 −0.11%（见 X）。
- 还不能进设计：v12c。第一阶段 13 组里，毛刺相对现行设计 +1.75%，分阶段 b=8 是 −0.70%。全量 112 组只完成 51 组。50 轮规则和迟滞没有分开测，迟滞要防的 RTT 抖动也不在这 13 组里。

### 7.34 局限

- 只有一类世界生成器；推迟的模块"没有收益"，可能是因为这个世界里没有它们要防的情况（严重失配、强非平稳）。
- 最优静态配置和 W 是事后挑的；2% 以内的差距多数只有 1–3 个种子，可能是噪声。
- 没有模拟 KV 紧张、NPU 路径、非 greedy 请求和 stop 字符串；长前缀只用一个成本倍数近似（7.6 节）。
- 开关的块长、两档阈值（3%、15%）和探测占比是在这个世界里比出来的，最终由 V6 和阶段 5 定。
- 多数场景只跑约 26 秒，开关的起步和结尾占比偏大；长时间运行的数字见 7.6 节第 1 点。
- 成本模型只模拟了 RTT 变化和按阶段交替的前缀长度，没有模拟同一 batch 里长短前缀混合；Target 的非 kernel 开销按固定的 2 ms 设定。
- 停止边界审计的结论来自这个合成世界。真实系统里 dA 同样能逐个算出（被接受路径没到叶子时为 0，到了叶子时用 bonus 判断），要在实测数据上重做。
- 规划器计时在 2 核虚拟机上、和其他模拟进程同时跑时测的，只能看量级；V8 不是 C++。
- 第 7 轮（7.8 节）的局限：
  - 只用了已有的 39 个实测格，大多每格只跑 1 次；lookahead 和 KV 复用都关，部署配置是开的。
  - 实测接受长度只有两个点，而且 τ=0.8 的那个是开着 lookahead 测的。
  - 评估只在 C1 一个设定下跑；C2、C3 只做了拟合，拟合出的成本结构相同。
  - 拟合范围最多到 b=8、N=16。解耦配置 K=16 在范围内，K=32 不在。
  - 只有短前缀；4096 前缀的数据来自合成填充提示，没有放进拟合。
- 第 8 轮（7.9 节）的局限：
  - 三种负载只在接受率参数上不同。真实数据集还会在请求长度、候选分布形状和位置相关性上不同。
  - 低接受率负载没有实测锚点。
  - 静态网格只跑了种子 7，在同一个样本上挑最优，对静态配置略有利。
  - 混合负载的最好静态配置是在种子 8 上事后挑的。
- 第 9 轮（7.10 节）的局限：
  - 新规则只在一个种子上评估，没有加自适应开关。
  - 按 batch 算账的规则用到了 Draft 的路径概率，真实 Draft 的概率校准情况可能不同，靠在线比值 c_i 修正。
  - K=32 在 b≥4 时超出成本拟合范围。
  - 模拟器里的在线学习本身有缺陷（SGD 慢、最大似然会分离），ClearTree 的数字反映的是这个实现，不完全是设计本身。
- 第 10 轮（7.11 节）的局限：
  - 每个场景只有 3 个种子，单个场景 1–2% 的差别可能是噪声。

  - 退出审计用的是这个合成世界里确定的真实路径。两层前瞻只看两层，更深的结构损失没有算。
