# ClearTree 相关测试结果

第 1–6 节的数据都在 `OPT_TREE_REMOTE` 上实测，是 ClearTree 的建模依据。第 7 节是合成模拟，不是实测。

数字来自用户在实验机上的运行，原始文件在实验目录的 `t0-run/`、`t0-run/gate/` 和 `raw/gate-window/` 下。除非另写，吞吐是两次重复的均值，单位 tok/s。

**共同配置：**
- Target：Qwen3-VL-32B，NPU 910c 两张卡，tp=2，page 128，`tree_paged_fia`，bf16，没有量化。
- Draft：Qwen3-VL-2B INT8，RTX 3090，page 1，Triton；图捕获 bs 1、2、4、8。
- 采样：temperature 0，`max_new_tokens=256`。
- 网络：单实验室内的 SSH 隧道，RTT 3–5 ms。

## 5. 4096 输出分叉的排查（`raw/gate-window/fork/`）

**现象：**
- D1（8 条前缀重复到 32，b=4）：投机 89.46，Target-only 104.76 / 104.83；差距 > 1 nat 的分叉 1 处（5.25 nat）。
- D2（32 条不同前缀，b=4）：投机 75.21，Target-only 98.80；差距 > 1 nat 的分叉 2 处（1.19 和 1.50 nat）。
- D3（b=1）：投机 42.15，Target-only 27.64。有一条前缀四次都在 t=72 写成 56056，Target-only 是 656，领先 6.81 nat。
- D4：这一轮 b=1 的验证 top-1/top-2 是 56056/5443，差 0.25 nat；b=4 时是 656/671，差 8.0 nat。两次的 KV 长度是 4172 和 4171，轮次切分差一位。

**逐项排除（同一条前缀，b=1，触发在 kv_len=4172）：**

| 嫌疑 | 结果 |
|---|---|
| 关闭 update overlap（S2） | 仍是 56056 |
| 退回 compact FIA（S1） | 252 MiB 工作区分配失败，请求退出，无结论 |
| 冷缓存 | 仍是 56056 |
| 惩罚 | 没有开启；惩罚前 top-1 就是 56056（logit 18.0 对 17.75） |
| h 父链、i/i′ 掩码、f 页内槽 | 都通过 |
| e/e2 写入槽和读取槽 | `out_cache_loc` 等于 `req_to_token[pool, 4163:4172]`，9 个槽互不相同；写入值和 cache 逐位相同 |
| j 第 0 层 V | 最大差 2⁻¹² 和 2⁻¹¹，是 bf16 噪声 |
| k/k′ 逐层 FIA | 64 层、两个 rank，和 fp32 GQA 的余弦 ≥ 0.9999 |
| 已提交前缀 4096..4166 的深层 K/V | 在 decode 对照的噪声内 |
| 量化（m3） | 没有量化，bf16 `UnquantizedLinearMethod` |
| 行耦合（m2） | M=1 单独重算和批量第 4 行逐位相同 |
| 子层局部误差（m1） | 第 30–45 层 8 个子层，投机最大 0.00366，decode 最大 0.00376 |
| 位置和树形（m4） | positions[4]=4167，cos/sin 逐位相同；这一轮是一条链 |

**残差：** 槽 0–3 的 64 层都在对照内。槽 4 从第 36 层起偏大，第 42 层相对范数 0.163（对照 0.054），第 43 层 0.333（对照 0.066），最后一层 0.722（对照 0.145），final norm 后余弦 0.60（对照 0.99）。

**结论：** 这个位置对数值噪声特别敏感，每个子层只有 bf16 噪声，逐层放大后翻转了结果。不是代码错误。

## 7. 合成模拟（2026-11-09 至 11-10，不是实测）

**这一节的数字都来自合成世界，不是实测。** 脚本和原始结果在 `test_sglang_liujg/clear_tree/sim/`（结果文件在 `sim/results/`），世界的设定见那里的 README。要点：
- 文本固定（greedy 语义），所有策略在同一批请求上配对比较。
- 参数按实测校准：b=1 时 OPT(8) 每轮约 3.5 个 token（实测约 3.6）；RTT 4 ms 时投机和 Target-only 在 b≈7–8 打平（实测短前缀 b≥7 时 Target-only 更快）。
- "最优静态"是在 (N ∈ {4, 8, 16}) × (τ 7 档) 的网格里事后挑的，偏强。
- 吞吐单位 tok/s；括号里的百分比相对最优静态。

**第 7 轮（7.8 节）推翻了 7.1–7.6 的收益结论，读之前先看 7.8：**
- 7.1–7.7 里的 OPT 用的停止规则和真实 OPT 不同：模拟器在"前沿最好路径分数 ≥ τ"时继续长；真实 OPT 在"前 N 路径概率之和 E 这一层的增量 > τ"时继续长（`opt_tree_ops.py` 的 `depth_rule`）。旧规则做出的静态基线平均弱约 4%，b=8 时弱 6–8%。旧网格也没有 N=2。
- 换成真实规则、网格加上 N=2 以后，在原来的世界里，ClearTree 核心相对最好的静态配置只高约 0.6%。原来的 +3.9% 主要来自偏弱的基线。

- 所以 E1、E2 用真实数据判断时，要看后悔或吞吐影响，不能只看偏差比例。
- 这项审计在真实系统里不需要额外的 Target 验证：补算前向给出被停下请求的真实下一层（dG），被接受路径到达叶子时，bonus token 就是叶子处的 y*（dA）。

- 给 ClearTree 已知的真实接受参数（oracle）也只有 6.5–7.2。
- 把宽度换成 W=2 也只有 6.4。

- **静态参数不能跨数据集通用。** b≥4 时，不同接受率的负载最优 τ 和 K 差别很大；用错极端负载的参数会损失 20% 以上。相近负载之间（中和高）损失 0–9%。
- **负载可以分开时：** 按数据集各调一套就够；同一种负载内，一套参数跨 b 最多损失约 4%。
- **负载混在同一个 batch 里时：** 单一折中配置 (4, 16, 0.4) 加开关已经接近静态能做到的最好，按类型分别设 τ 没有用。ClearTree 只在 b=4 多约 2%，在 b=1 和 b=8 没有优势。
- **ClearTree 目前做不到"不调参、自动适应各种负载"。** 它在高接受率负载下会少长层，这是规划本身的问题，要先修。
- **实测检验：** 在 2–3 个数据集上用现有 OPT 扫 τ，看最优 τ 是否不同，以及互换参数损失多少（plan.md 第 13 节的数据集）。

### 7.10 定位 ClearTree 少长层的原因，以及两条更简单的规则（第 9 轮，2026-11-10）

- **主因是接受率被低估：** 已知参数时差距基本消失。停止边界审计显示，高接受率下被停下的请求，实际收益比预测高 10–24%；下一层的快照预测是准的（比值 1.01）。
- **模拟器自身的原因：** 模拟器的在线学习把全局截距 a 从 0 开始、每个标签只走 0.01 步（`feasibility.py`）。高接受率下标签几乎全是命中、预测概率接近 1，梯度很小，a 收敛很慢。
- **改成最大似然拟合后，** 整体校准变得无偏（实际 / 预测 0.97–0.98），差距在 b=4 收回一半，b=8 只收回一点。但高接受率下几乎没有失败标签，截距和斜率直接撞到上下限（完全分离），需要先验或正则化。
- **K 固定 32 能收回 1–3 个百分点；成本裕量 1.0 没有一致的效果。**
- **已知参数时 b=8 仍差 4.9%：** 那里最优静态配置用 W=2，ClearTree 用 W=4。具体原因没有再查。
- **对设计的含义：** logistic 校准在接受率接近 1 时会饱和，几乎没有失败样本。高接受率是它的弱点，而停止边界审计里"实际 / 预测"的比值能在线发现这个偏差。

**R：两条更简单的规则。**

- **按 batch 算账（`BatchAccount`）：**
  - 每个请求下一层的收益 = c_i × ΔE_i。ΔE_i 是刚加的一层让它的前 K 路径概率和增加了多少，和真实 OPT 判断用的是同一个信号；c_i 是在线校准（实际接受数 / 预测的前 K 质量），按请求算，向全体均值收缩。
  - 每层保留收益最高的 m 个请求，m 只能是当前活跃数或更小的图档（8、4、2、1）；"它们的收益之和 − Θ* × 这一层的成本"大于 0 才继续。Θ* 和每档的层成本都在线学。
  - 不按负载调任何参数。
- **接受率 → τ（`OPTRhoTau`）：**
  - 在线估计按深度的接受率 ρ = Σa / (Σa + 停在树内的轮数)。这个量几乎不随 τ 变：低、中、高三种负载分别约 0.65、0.85、0.97。
  - 用 ρ 判断负载类别，再查一张从 7.9 节网格离线拟合的 τ 表。(W, K) 取 (4, 32)，它各负载的最优 τ 平均能拿到各负载最优的 97.9%。

  - 纯负载：各负载调好的最优静态配置（样本内）。
  - 混合负载：混合负载的最好静态配置（7.9 节，事后挑）。
  - 分阶段负载（先低、再高、再中）：同一批请求上跑过的静态候选里最好的一个。
- **按 batch 算账的短板在 b=1：** 那里最优宽度是 8，规则用的是 4。改用 W=8、K=32 以后（`d9b.json`），b=1 时低、中、高分别 −1.9%、−0.5%、−0.4%，混合负载 +0.4%。
- **按 b 选宽度后的整体结果：** b=1 用 W=8、K=32，b≥4 用 W=4、K=32。纯负载 9 格平均约 −0.2%，最差 −4.8%（高接受率，b=8）。b≥4 改用 K=16（在拟合范围内）时，平均约 −0.4%，最差 −7.1%。
- **混合和分阶段负载：** 按 batch 算账比事后挑的最好静态配置高 3–7.5%，和 ClearTree 相当（ClearTree K=16 高 0.2–2 个百分点）。
- **b=8 的混合负载：** Target-only（219.8）比所有静态配置都快。ClearTree K=16（220.2）和它持平，按 batch 算账（216.0）低 1.7%。
- **接受率 → τ 基本没用：** 纯负载平均 −2.5%，混合和分阶段负载 −1.2% 到 +1.1%。按类别整批切换 τ，跟不上请求之间的差异。

**结论（合成，待实测确认）：**
- 按 batch 算账的简单规则，加上按 b 选的 W，在不按数据集调参的情况下，基本追平了"每个数据集各调一套"的静态配置（平均约 −0.2%）。在混合负载和随时间变化的负载下，它比任何单一静态配置高 3–7.5%。
- 它不需要两段式 GLMM、快照库、子集 DP、K_g/K_v 和 C++ 规划器。和 ClearTree 核心相比只差 0–2 个百分点，而且在高接受率下比 ClearTree 稳。
- ClearTree 自身的问题出在接受率校准：高接受率下 logistic 模型会饱和，在线 SGD 收敛慢，最大似然会完全分离。如果保留 ClearTree，校准要换成能处理接近 1 的接受率的形式，或者用停止边界审计的"实际 / 预测"比值在线修正。

### 7.14 W 和 K 能不能在线选（第 13 轮，2026-11-10）

脚本：`ext11.py`（`BatchAccount4`：在线选 K、在线选 W）、`run13.py`、`analyze13.py`。结果：`r13.*.jsonl`、`analyze13.txt`。

**设定：** 规则都是修订后的第十版（首位 top-1 分类、按轮冻结、Θ_b、b=1 的保守开关）；种子 8–10；b = 1、4、8。

**负载：**
- 已知三种：低、中、高。
- 没见过的四种：
  - 中低（a=2.0）、中高（a=3.5）；

**方案：**
- **查表：** 第十版三.1 的表。
- **在线选 K：** K ∈ {8, 16, 32}，验证前比较"多验证那几个节点的 c_i × 路径分数之和"和"Θ_b × 验证耗时差"。验证耗时当作已经测好（相当于 V2 的结果），不在线学。

  - 估计各 W 下的每轮吞吐，可验证的深度上限取 ⌈K/W⌉+1；
  - 选吞吐最大的 W，切换要高出 2%。

- **对照：** 同一规则下，6 种固定 (W, K) ∈ {2, 4, 8} × {16, 32} 里，事后挑出的最好一种。

### 7.15 用已提交文本配对回放选 (W, K)（第 14 轮，2026-11-10）

脚本：`ext12.py`（`BatchAccount5`：配对回放、截窄审计）、`run14.py`、`run14b.py`（回放改用实测的层耗时）、`analyze14.py`。结果：`r14.*.jsonl`、`r14b.*.jsonl`、`analyze14.txt`。

**回放怎么做：**
- **依据：** greedy 解码时，提交的文本和树形无关。所以文本一旦已知（模拟里用 H，相当于之后几轮提交的 token），每棵已经建好的树都能按别的选项重新算一遍。
- **对每个候选 (W′, K′)：**
  - 宽度：把树逐层截成全局 top-W′（W′ ≤ 本轮的 W）；
  - 验证集：取前 K′ 个节点；
  - 接受数：真实路径沿这个验证集能走多深，再加 1 个 bonus；
  - 耗时：在实际耗时上加减差值，包括首层和各层的层成本差、验证耗时差（验证耗时按已测好处理）。
- **比较方式：** 每个候选都和当前选项在同一批轮次上配对比较。比当前更宽的候选，只能用 5% 的探索轮（真的用宽一档建树）来比较。
- **切换规则：** 按并发档分别维护，每 20 轮判断一次，高出 3% 才切换。回放第一次切换之前，跟着表走。

**场景：**
- 没见过的四种负载；
- 验证 ×10、Draft 快一倍、Draft 慢一倍，各用中、高两种负载；
- b = 1、4、8，种子 8–10。

**对照：** 同一规则下，6 种固定 (W, K) 里事后挑出的最好一种。

| 世界 | 查表 | 只在线选 K | 回放（层耗时在线学） | 回放（层耗时实测） |
|---|---:|---:|---:|---:|
| 没见过的负载（12 格） | −0.26%（−1.8%） | −0.10%（−0.9%） | −1.23%（−4.2%） | −0.20%（−1.2%） |
| 验证 ×10（6 格） | −2.89%（−8.8%） | −0.62%（−2.7%） | −1.63%（−3.9%） | −0.81%（−1.6%） |
| Draft 快一倍（6 格） | −0.39%（−0.9%） | −0.10%（−0.4%） | −1.42%（−3.6%） | −0.60%（−1.2%） |
| Draft 慢一倍（6 格） | −0.51%（−1.5%） | −0.28%（−1.2%） | −0.90%（−3.1%） | −0.21%（−0.7%） |
| 全部 30 格 | −0.86% | **−0.24%** | −1.28% | −0.41% |

（相对事后最好的固定 (W, K)；括号里是最差格。）

**截窄近似的审计（真按窄一档的 W 建树，和截窄的结果比较；深度、K 相同）：**
- 5–7% 的"请求 × 轮"上接受数不同；
- 平均差 −0.006 到 +0.022 个 token，相对接受数在 −0.16% 到 +0.54% 之间。
- 所以"宽树截窄当作窄树"的误差很小，可以用。

**回放在线学层耗时时为什么会输：**
- b=1 时，层成本模型只见过当前宽度的层，别的宽度只能按"图档 × W"等比例外推。可按拟合，每层约 5 ms 是固定开销，所以窄层的耗时被低估了约 30%。
- 回放因此高估了窄选项。追踪里，b=1、中高接受率时它估计 (2, 16) 比 (8, 32) 好 12.1%，实际是差的。
- 切过去以后，更宽的选项只能靠探索轮来比较，攒样本很慢，于是卡住了。
- 改用实测的层耗时后，b=1 的损失都收到 0.4% 以内。

**结论（合成）：**
- **接受数用回放算是准的，耗时必须来自实测：** 部署时用微基准测好每个 (图档, W) 的 Draft 层耗时，和 V2 测验证耗时一起做。
- **在这些世界里，只在线选 K 是最好的方法**（30 格平均 −0.24%）。回放加实测层耗时略差一点（−0.41%），差距主要来自约 3–4% 的探索轮，以及多候选比较的噪声。
- **W 的余地很小：** 大多数场景里事后最好的 W 就是表里的 W。回放只在少数格上更好，例如验证 ×10、高接受率、b=4：−1.6% 对只在线选 K 的 −2.7%。
- **回放更适合做审计工具：** 检查表里的 W 是否还合适，同时为停止边界审计、退出审计提供数据；不适合直接当控制器。

### 7.18 审稿意见 16：跨 K 停止、跨 K 边际校准、没在用的 K 变便宜（第 17 轮，2026-11-10）

- **跨 K 边际校准（第 4 条）：**
  - 单一 c_i 对排名靠后节点的偏差和接受率有关：低接受率高估，中高接受率低估。
  - 在审稿人指出的那一格，f_band 收回 2.4 个百分点；其他格基本持平。
  - 同树重选 K 只能看到很小一部分影响，审计要直接看 f 偏离 1 的程度。
- **没在用的 K 变便宜（第 5 条）：**
  - 第二版检测确实看不到，在 b ≤ 4 时可能损失 3–6%。
  - 低频探测的性价比低：收回约一成，不变时持续花 0.2–0.4%。
  - 应该用部署、重新捕获图之类的事件触发全档重测，而不是靠随机探测。

### 7.19 局限

- 只有一类世界生成器；推迟的模块"没有收益"，可能是因为这个世界里没有它们要防的情况（严重失配、强非平稳）。
- 最优静态配置和 W 是事后挑的；2% 以内的差距多数只有 1–3 个种子，可能是噪声。
- 没有模拟 KV 紧张、NPU 路径、非 greedy 请求和 stop 字符串；长前缀只用一个成本倍数近似（7.6 节）。
- 开关的块长、两档阈值（3%、15%）和探测占比是在这个世界里比出来的，最终由 V6 和阶段 5 定。
- 多数场景只跑约 26 秒，开关的起步和结尾占比偏大；长时间运行的数字见 7.6 节第 1 点。
- 成本模型只模拟了 RTT 变化和按阶段交替的前缀长度，没有模拟同一 batch 里长短前缀混合；Target 的非 kernel 开销按固定的 2 ms 设定。
- 停止边界审计的结论来自这个合成世界。真实系统里 dA 同样能逐个算出（被接受路径没到叶子时为 0，到了叶子时用 bonus 判断），要在实测数据上重做。
- 规划器计时在 2 核虚拟机上、和其他模拟进程同时跑时测的，只能看量级；V8 不是 C++。
- 第 7 轮（7.8 节）的局限：
  - 只用了已有的 39 个实测格，大多每格只跑 1 次；lookahead 和 KV 复用都关，部署配置是开的。
  - 实测接受长度只有两个点，而且 τ=0.8 的那个是开着 lookahead 测的。
  - 评估只在 C1 一个设定下跑；C2、C3 只做了拟合，拟合出的成本结构相同。
  - 拟合范围最多到 b=8、N=16。解耦配置 K=16 在范围内，K=32 不在。
  - 只有短前缀；4096 前缀的数据来自合成填充提示，没有放进拟合。
- 第 8 轮（7.9 节）的局限：
  - 三种负载只在接受率参数上不同。真实数据集还会在请求长度、候选分布形状和位置相关性上不同。
  - 低接受率负载没有实测锚点。
  - 静态网格只跑了种子 7，在同一个样本上挑最优，对静态配置略有利。
  - 混合负载的最好静态配置是在种子 8 上事后挑的。
- 第 9 轮（7.10 节）的局限：
  - 新规则只在一个种子上评估，没有加自适应开关。
  - 按 batch 算账的规则用到了 Draft 的路径概率，真实 Draft 的概率校准情况可能不同，靠在线比值 c_i 修正。
  - K=32 在 b≥4 时超出成本拟合范围。
  - 模拟器里的在线学习本身有缺陷（SGD 慢、最大似然会分离），ClearTree 的数字反映的是这个实现，不完全是设计本身。
- 第 10 轮（7.11 节）的局限：
  - 每个场景只有 3 个种子，单个场景 1–2% 的差别可能是噪声。
  - 混合和分阶段负载的对照配置是在种子 8 上挑的，种子 8 对它是样本内。
  - 每次模拟的请求数有限，收尾阶段占时间的 5–10%，比持续到达的真实服务多。
- 第 11 轮（7.12 节）的局限：
  - (W, K) 表和 ρ̂ 阈值都来自三种合成负载，换到真实数据集要重定。
  - 简化表有一格是看过评估结果后改的。
  - 没有测"b 小时按 token 数分块"的开关。
- 第 12 轮（7.13 节）的局限：
  - 退出审计用的是这个合成世界里确定的真实路径。两层前瞻只看两层，更深的结构损失没有算。
  - b=5 改归 K=16 一档没有单独模拟。
  - 首位 top-1 的阈值 0.84 来自合成负载。
- 第 13 轮（7.14 节）的局限：
  - 对照"事后最好的固定 (W, K)"是在同一批种子上挑的，偏强。
  - 在线选 K 用的验证耗时是模拟世界的真值，实际要靠 V2 测量。
  - 只模拟了"验证变贵"这一种成本变化，没有模拟 Draft 变快或变慢（第 14 轮补上了）。
- 第 14 轮（7.15 节）的局限：
  - 模拟器里一两轮之后就能拿到真实路径；实际要等后面的轮次提交，深层节点要多等几轮。
  - 回放只比较"相同深度、更窄的宽度、不同的 K"，没有回放更深的情形。
  - 层耗时和验证耗时用的是模拟世界的真值，代表"部署时测好"的理想情况。
- 第 15 轮（7.16 节）的局限：只回放了相同深度下的宽度表，没有让深度随宽度表重新优化；只有 2 个种子。
- 第 16 轮（7.17 节）的局限：
  - 台阶形的验证耗时是假设的形状；
  - 成本变化只模拟了一次突变，没有模拟缓慢漂移或反复变化；
  - 漂移检测的阈值和测量长度都是在这个世界里试出来的。
- 第 17 轮（7.18 节）的局限：
  - 跨 K 停止的诊断和真值前瞻预知的是 Draft 路径分数的增量，不是实际接受；"错过的价值"按校准后的预测计。
  - f_band 的同树回放直接用了完整的未来文本；真实系统里深层节点要等后面几轮提交才有标签。
  - 模拟器里每个请求的难度不随时间变，Draft 的概率偏差只来自生成器本身，真实 Draft 的偏差形状可能不同。
  - "K=32 变便宜"是一次性的台阶变化；事件触发的重测没有单独模拟，只用"触发后修正值准确"推断。
  - 低频探测需要累计到每个 K 至少 8 个样本，运行较短时（b=4）常常凑不够，结果受运行长度影响。
