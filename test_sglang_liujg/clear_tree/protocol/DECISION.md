# 判据

开跑之前写在当次的 `question.md` 里，并引用下面的条目。改判据先改本文件，理由不能依赖即将跑的那一次结果。服务包里的 `design/progress/decisions.md` 只在一次运行判定「改变规则」或「放弃一条路」之后追加。

## 比较

- 主判据是每层耗时，以及按请求配对、只计到第一次分叉的接受长度。分叉之后的 token 只进总体统计。
- 吞吐是次判据。系统收益计入预热、K 探测、窄档探测和宽档探索。算法质量可以另报不含这些轮次的数字，两列都要有运行号。
- 噪声门槛取同一场次 A/A 带宽和 1% 中的较大者。低于这个门槛的差距记为未分辨，不写成改进。
- 比较只在同一场次内做，顺序是 A B A B。不把不同日期的吞吐并成一格。
- 一次运行只改一个因素。修 bug 和改算法分成两次运行。

## 作废

- 某次 Target 验证前向的每轮中位数偏离同组中位数超过 10% 时，该次作废。目录保留，`meta.json` 里 `voided` 为 true，汇总时跳过。
- 扫 τ 时只重启 Draft。每组第一格确认 Target 没有因为形状拒绝，也没有会话重置失败。

## 记录

- 每个数字对应 `validate/<实验>/<运行号>/` 里的一个文件。
- `meta.json` 记下两端 git hash、工作区是否有未提交改动、账本开关、KV 桶、宽度和验证数候选、温度。不写地址、口令和模型路径。
- 工作区不干净时，把 diff 放进该次运行的 `raw/code.patch`。
