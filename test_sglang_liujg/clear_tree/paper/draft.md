# ClearTree：按实测成本决定树宽和验证长度的跨机投机解码

本文描述现行服务 `CLEAR_TREE_REMOTE` 的算法。规则以服务包 `python/sglang/srt/speculative/clear_tree_remote/README.md` 和同目录代码为准。`design/` 记录设计选择和合成模拟，不判断正在跑的服务。没有运行号的实验格子留空，不填估计数字。

## 1. 问题

树形投机解码让小模型按层起草，大模型一次验证树上的若干节点。固定宽度 N 和固定阈值 τ 把两件成本不同的事绑在一起：Draft 每多长一层要做一次宽度为 W 的前向，Target 每多验证一个节点主要改变验证前向的长度。跨机部署里，Target 与 Draft 不在同一台机器上，一轮还要付一次往返。

ClearTree 把层宽 W 和验证数 K 分开。W 决定这一轮树有多宽，K 决定送去验证的节点有多少。两者都从一张平表起步，只有两端都打开账本时，才用实测的层耗时和验证耗时在线调整。账本关闭时，每一轮都是平表上的 W 和 K，停层仍用 τ。

层宽与验证数分开、按价格决定是否继续，分别与 EAGLE 的重排和 TollTree 的价格门槛同类。本文要测量的是：在跨机、图按档捕获的服务里，用同一套实测成本做整批算账，以及用截树回放调宽度，这些近似留下多大的损失。

## 2. 系统

Target 负责验证，Draft 负责按层建树。两端用独立算法 `CLEAR_TREE_REMOTE`，角色由 `--clear-tree-role` 指定，参数与 OPT 的 `--opt-tree-*` 分开。控制信息和 token 走两端之间的 RPC。握手仍用 `--clear-tree-width`，它是线上约定的宽度，不是候选列表。

图和缓冲的容量由 `--speculative-num-draft-tokens` 给出。Target 的容量是最大 K 加 1，默认 65。Draft 的容量是最大层宽 W，默认 64；bonus 缓冲是最大 W 加 1，默认 65。省略该参数时按这个容量填上；显式传入的值必须等于它。候选由 `--clear-tree-ks` 和 `--clear-tree-widths` 指定，未指定时都是 2、4、8、16、32、64。平表要求宽度里有 4 和 8、验证数里有 8 和 16，否则拒绝启动。

CUDA 和 NPU 的图按该进程的 batch 列表捕获，这个列表不是算法常量。启动时捕获每一个候选，不读取层耗时或验证耗时，因为这时还没有请求样本。Target 的验证图默认是 65、33、17、9、5、3，另加单 token decode 的 1。回放时按本轮的 K+1 选图。Draft 的层图默认是 64、32、16、8、4、2，bonus 图默认是 65、33、17、9、5、3，另加 decode 的 1。bonus 只在 batch 1 捕获。

NPU 上，验证图再按 KV 桶拆开。默认桶是 256、512、1024、2048、4096。`speculative_eagle_topk` 大于 1 时，每个验证宽度、每个桶各抓一张图；`ntpb = 1` 的 decode 图不拆桶。前缀加本轮验证长度超出最大桶时，这一轮走 eager，不回放图。启动抓图是系统开销，不是策略在选形状。

## 3. 一轮决策

服务宽度和 τ 上的验证数从平表起步。一批只有一个请求时 W 为 8、K 为 16；其余请求数 W 为 4、K 为 8。在线 K 和在线 W 要求 Target 与 Draft 都设置 `SGLANG_CLEAR_LEDGER=1`。只开一端时，价格、校准比或验证样本缺一块，决策留在 τ 加平表 K。账本默认关闭。

一轮里，停层和选 K 用同一个价值：

`J_K = 校准后的前 K 个路径分数之和 − Θ × 该档验证耗时`

层拟合够样本之后，停层枚举还能继续长的请求人数，只保留继续价值更大的那一组。继续的价值要高于现在停下、按最好的 K 验证的价值，才再长一层。验证样本够了以后，K 在不超过覆盖上界的已捕获档里取 `J_K` 最大的一档。覆盖上界是装得下「建树宽度 × (max_depth − 1)」个节点的最小档；选 K 时再收到各请求的实际节点数。普通轮的建树宽度就是当前服务宽度，所以是否就绪、选哪一档 K，都只看这个宽度的覆盖档。

下列轮次用 τ，并且 K 锁在平表：前 10 轮、K 探测轮、样本不够的轮、非贪心轮，以及批建树失败后的回退轮。这一档的 KV 桶装不下时，退到装得下的最大档。回退轮不加轮次、不取探测、不进回放统计，batch 取整个包的请求数。τ 轮的停层按本轮锁定的 K 算质量，不是按层宽。`SGLANG_CLEAR_LOCK_K` 可以把验证数锁在指定档，停层仍用 τ，并且不消耗探测。

K 探测的上界是宽一档的覆盖档；没有更宽档时，是服务宽度的覆盖档。探测轮数达到 max(54, 已过轮数的 5%) 后不再取探测。这一格还有档没有样本时留在平表；样本已经齐则继续在线选 K。

## 4. 两个成本模型

层耗时在 Draft 上拟合。每次层前向记一个样本。回归特征是截距、图档和活跃请求的前缀之和。岭项按特征给：截距 0、图档 1e-6、前缀之和 128²。同一宽度凑满 4 个样本之后才用于决策。查询的前缀之和比见过的最小或最大再超出 max(128, 这段跨度)，或者预测不大于 0 时，这一档没有层耗时。服务宽度因此走平表，回放里这个候选不配对。

验证耗时按 Target 后端分开。`SGLANG_CLEAR_TARGET_BACKEND=cuda`（默认）时，Draft 用时间账本的 `T_K` 更新验证模型。设为 `npu` 时，Draft 仍记录 `T_K`，但不拿它更新验证模型；Target 用设备时间 `device_us` 和 NPU 特征拟合。选 K 用的是最近的 `device_us` 样本：事件完成时写在验证日志里，未完成时下一次 poll 补记并更新同一条回归。Target 上另有一条验证回归，只打日志，不参与选 K。完成的 `device_us` 随下一轮请求回到 Draft。

NPU 的桶是能装下最长前缀加 K+1 的最小桶。同一个 `(batch, K, 桶)` 有样本之后，才有这一档的验证耗时。样本不够、正在做 K 探测，或者非贪心时，仍用 τ，K 锁平表。

某个请求的前缀增长超过本轮树深加 1 时，这一轮记为 `target_gap`，不进价格、校准比、层回归和回放。Target 会话号变大时，清验证表、探测计数、层回归、只写日志的验证回归、回放累计和还没结算的校准比，并丢掉还没关闭的那一轮。服务宽度、价格和已经结算的校准比保留。下一合格轮重新做窄档探测。

## 5. 宽度怎么换

换 K 和换 W 不是同一种反事实。同一棵树上改验证数可以按已提交文本重算，这个结果只作审计。改宽度要把树截窄或换成相邻的更宽一档，退出和深度沿用原树，所以是近似。这个近似用来驱动服务宽度，不设偏差门。偏差按 (宽, 窄) 记账，只写在日志里：真建成一档时累计这一档的真实 token 和耗时；建成宽档且回放里有更窄一档并有耗时时，累计这次截树，并用这一轮真实宽树做分母。某一对至少各有 30 轮才算出偏差。

账本开着时，预热、K 探测、锁 K 和非贪心之外的合格轮里：

- 当前服务宽度的相邻窄一档如果连续 300 个合格轮没真跑过，就真跑 `probe_w`。这一档的层样本还不到 4 个时，这次最多连续 4 轮，样本满 4 就停；已经满了就仍是 2 轮。计数从 300 起步，所以预热后的第一个合格轮就是第一次。`probe_w` 优先于同一轮的探索，不进回放统计。K 照常选。层回归还没有样本或前缀超出已见范围时走平表。
- 其余每 20 个合格轮真建比当前服务宽度大的相邻一档，种类记为 explore。已经是最大档时这一轮留在当前宽度。探索轮如果还在 τ，不进回放统计。

判定按 batch 所在的档进统计的轮数，每 20 轮一次。比当前窄的相邻一档至少 30 个配对轮、比当前宽至少 10 个配对轮，并且增益超过 3%，才换成该档。往更窄只换成相邻的更小一档。增益更大但不是这次切换目标的档只记在 `would_w` 里。变宽没有额外的门。模拟里出现过一次切错的变宽，损失约 0.7% 到 1.9%，这是已知风险，不是实测结论。不想让服务宽度走到 16 以上时，启动用 `--clear-tree-widths 2 4 8`。

回放审计不了「停得太早」：已经停下的层没有被建成，截树也看不到那些节点。

## 6. 会影响结论的边界

对照实验必须写明这些开关，否则数字不能并排。

- 账本默认关闭。关闭时不取探测，每一轮都是平表的 W 和 K，停层用 τ，质量按这个 K 算。
- 只开 Target 或只开 Draft 时，决策留在 τ 加平表 K。
- 日志和拟合只在 tp rank 0。Draft 的 `tp_size > 1` 直接拒绝启动，因为其他 rank 会另走一套 τ。
- NPU 的 page size 是 128，CUDA 是 1。两边的验证耗时模型不能混用。
- 超出最大 KV 桶的验证走 eager。图内时间和 eager 时间要分开报。
- 未设置 `--max-running-requests` 时，运行中的请求上限改为 48。实际捕获的 batch 列表是该进程的图 batch 列表与这个上限的交集，不是算法常量。
- 温度 0 时验证是贪心的。非贪心轮不进入在线选 K，也不进入换宽统计。

## 7. 实验

本节只定协议。表中没有运行号的格子是待测，不填数字。一次运行的记录在 `validate/<实验>/<运行号>/`。合成模拟在 `sim/results/`，汇总在设计进展的第 7 节。那些结果用来说明设计为什么收成现在的规则。合成填充前缀上的接受长度高于自然提示，不能拿来下性能结论。

主判据是每层耗时，以及按请求配对、只计到第一次分叉的接受长度。吞吐是次判据。系统收益要把预热、K 探测、窄档探测和宽档探索都算进去。噪声门槛取同一场次 A/A 带宽和 1% 中的较大者。比较只在同一场次内做，A/B 交替。某次 Target 验证前向的每轮中位数偏离同组中位数超过 10% 时，该次作废。

对照是四条：

| 对照 | 账本 | 宽度和验证数 | 停层 |
|---|---|---|---|
| Target-only | 无 Draft | 无 | 无 |
| 固定 OPT | 关 | 固定 N 和 τ | τ |
| 平表 | 关 | 平表 W、K | τ |
| ClearTree | 两端开 | 在线 W、K | `J_K`，样本不够时退回 τ |

端到端还没有保留的运行。

| 对照 | 运行号 | 接受长度 | 轮时 | 吞吐 | 备注 |
|---|---|---|---|---|---|
| Target-only | 待测 |  |  |  |  |
| 固定 OPT | 待测 |  |  |  |  |
| 平表 | 待测 |  |  |  |  |
| ClearTree | 待测 |  |  |  |  |

消融每次只关一件事：冻住 W、冻住 K，或停层只用 τ。宽度轨迹单独记录每个 batch 档的服务 W、配对轮数，以及是否切回。正确性在温度 0 下与 Target-only 对到第一次分叉。延迟实验用用户态代理改变往返；真实链路上只复核一两个点，用来确认代理没有改变结论的方向。

层耗时和验证耗时各自有一格，用来检查拟合能不能被决策使用：前缀超出见过范围时是否拒绝预测，KV 桶之间是否有台阶，eager 是否被单独标出。这些格子的数字同样等待运行号。

## 8. 局限

换 W 的回放沿用原树的退出和深度，偏差只作诊断，不阻止切换。因此服务宽度可能切到更宽的一档再留在那里。停得太早的那些层没有被建成，现有回放看不到。很少被选中的 K 主要只有探测轮的样本，验证耗时在这些档上更不稳定。NPU 按桶计验证时间，CUDA 按前缀之和计，把一边拟合的系数用到另一边会选错 K。Draft 不能做张量并行，账本不能只开在一端。启动要把每个 batch、每个 K+1、每个 KV 桶的图抓完，这个成本发生在任何策略之前。
